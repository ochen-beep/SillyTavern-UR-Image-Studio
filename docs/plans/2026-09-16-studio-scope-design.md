# Studio scope: генерация вне чата (welcome screen)

Дата: 2026-09-16
Статус: фаза 1 реализована
Спецификация-обсуждение: чат ZCode 2026-09-16 («работа с генерацией вне чата, на начальном экране»)

## Задача

На начальном экране SillyTavern (список чатов, чат не открыт) неудобно заниматься
подготовительной работой: строить и проверять референсы, генерировать картинки
«для всех», сортировать галерею. Раньше вкладка «Генерация» там показывала пустое
состояние, конфиг и привязки референсов писались в транзиентный `chatMetadata`,
а галерея фильтровалась по несуществующему chatId. Генерации в чате персонажа
засоряли чат.

## Ключевое решение

**Не подделывать чат.** `state.currentChatId = ctx.chatId` остаётся `null` на
welcome-экране: пути, которым нужны сообщения (автогенерация, inline-сканер,
постнавигатор), честно неактивны. Вместо этого генерационный контур получает
явный «скоуп» — `resolveActiveChatId()`: реальный chatId при открытом чате,
`STUDIO_CHAT_ID = '__uris_studio__'` иначе.

Префикс `__` выбран потому, что реальные chatId в ST имеют вид «Персонаж - N»
или `group_<id>` — коллизия невозможна. Идентификатор попадает в ключи драфтов
(localforage, encodeURIComponent-безопасен) и `provenance.chatId` карточек.

## Компоненты (фаза 1 — реализовано)

### src/studio-scope.js (новый)

- `STUDIO_CHAT_ID`, `STUDIO_MSG_ID = 0`, `STUDIO_IMAGE_FOLDER = 'URIS Studio'`.
- `isStudioActive()` / `resolveActiveChatId()`; `isStudioActive` деградирует в
  false, если контекст ST недоступен (node-тесты).
- Файловый стор `uris_studio.json` через `createFileStore` — тот же паттерн, что
  uris_refs/uris_gallery/uris_param_presets. Внутри конверт **той же схемы v5**,
  что у чат-биндинга: `{schemaVersion: 5, config, refs}`.
- `getStudioBinding()` / `saveStudioBinding()` — сырой读写 для маршрутизации;
  запись через `store.replace()` (мутатор файлового стора правит зеркало на
  месте, поэтому цельная замена значения идёт через replace-ветку).
- `ensureStudioStoreReady()` / `flushStudioWrites()` / `flushStudioWritesOnUnload()`
  / `resetStudioStoreForTests()`.

### Маршрутизация (две главные точки)

- `src/chat-binding.js`: `getBinding()`/`setBinding()` при активной студии читают
  и пишут студийный конверт; `loadChatConfig()`/`patchChatConfig()` предварительно
  ожидают `ensureStudioStoreReady()` — иначе незагруженный стор ответил бы null,
  дефолт записался бы поверх персистного конфига. Вся нормализация
  (`normalizeChatBinding`) работает без изменений.
- `src/refs-library.js`: `_rawBinding()` и `saveChatRefs()` аналогично уходят в
  студийный стор (`saveStudioChatRefs` — те же инварианты, что у чат-ветки).

После этого бесплатно оживают: настройки модели/параметров/шаблона в студии,
whitelist референсов «для всех», `buildCandidates()` и снапшот конфига пайплайна.

### Драфты (src/generation-drafts.js)

Ключ `uris_generation_draft:__uris_studio__:0` легален без изменений
`generationDraftKey`. Единственное семантическое изменение: в
`getGenerationDraft` драфт студии **не инвалидируется** по несовпадению хэша
«сообщения» — текст сцены в студии это редактируемый ввод, а не неизменяемый
пост; построенный промпт — источник истины. Текст сцены хранится в новом
опциональном поле драфта `sceneText`. Чатовые драфты инвалидируются как раньше
(тест-страж).

### Вкладка «Генерация» (src/ui/tab-generate.js)

- `activeScope(root)` — единая точка «какой драфт редактируется»: чат →
  (chatId, currentMsgId, текст поста), студия → (STUDIO_CHAT_ID, 0, текст
  textarea `#urisScene`). Все бывшие чтения `ctx.chat[msgId].mes` в обработчиках
  переведены на него (автосейв промпта, prepareRunInput, параметры, шаблон,
  модель, коррекции референсов, whitelist, очередь).
- Разметка: вместо постнавигатора — бейдж «Студия»; вместо read-only эксерпта —
  редактируемая textarea сцены с автосейвом и живым пересчётом превью
  референсов; селекторы «Автоматизация» и «Флоу генерации» скрыты (без событий
  сообщений им не с чего срабатывать; их дефолты живут в студийном конверте).
- `buildGenerateViewModel`: stale-бейдж для студии всегда false.
- `syncCancelState`/`onGenerationStart` сравнивают msgId со скоупом корня, а не с
  `state.currentMsgId`.

### Очередь (src/pipeline-queue.js)

- `createQueueItem` кладёт `messageText` в элемент только для студийных айтемов.
- `processQueue` для студии берёт текст из айтема (перечитывать нечего), не
  отбрасывает айтем по stale-chat/stale-hash — скоуп студии не зависит от смены
  чатов, генерация доигрывает в свой скоуп.

### Галерея (src/ui/tab-gallery.js)

`resolveActiveChatId()` вместо `getCtx().chatId`: без чата показывается скоуп
студии + бейдж «Студия»; текст очистки учитывает скоуп. Карточки студийных
генераций получают `provenance.chatId = '__uris_studio__'` автоматически —
стемпинг уже шёл из request.chatId через image-api.

### Прочее

- `native-image-storage.getCharacterImageFolder()`: без чата — папка
  `URIS Studio` (не legacy).
- `index.js`: `ensureStudioStoreReady` в стартовый Promise.all; flush-вызовы в
  visibilitychange/pagehide/cleanup; конфиг загружается безусловно (роутинг сам
  выбирает источник); новый слушатель `uris:chat-changed` перерисовывает
  активную вкладку «Генерация»/«Галерея» при переключении чат ↔ welcome.
- CSS: `.uris-scene-area`, `.uris-gallery-scope`, `.uris-studio-scene`.

## Осознанная граница

Per-chat привязки референсов (какой набор активен в конкретном чате) остаются
чат-scoped — их и есть смысл настраивать в чате. Студия даёт глобальный пул
(был и раньше) + собственную привязку + генерации и галерею вне чата.

## Подводные камни (проверено тестами)

- Нигде не присваивать `state.currentChatId = STUDIO_CHAT_ID` — иначе
  `triggerIfMatches` (events.js) примет студию за открытый чат.
- Тестовые стабы контекста обязаны ставить `chatId` там, где проверяют
  чат-scoped поведение: `chatMetadata` в проде существует только при открытом
  чате, и роутинг по `!chatId` на такое поведение опирается.
- Порядок ready→read→write студийного стора: читать без ready — получить дефолт
  и записать его поверх персистного конфига.
