# Дизайн: просмотрщик и кроп v2 (нативные, без вендоров)

Дата: 2026-09-25. Ветка: `feat/native-viewer-crop`.

## Диагноз past-версии (что «хромало»)

Проверено живьём на стенде (`tests/manual/viewer-harness.html`, 480×800):

1. **Двойной transform при FLIP-анимации.** `animate()` вешал WAAPI-анимацию
   на `.uris-viewer-frame`, оставляя inline-transform на `<img>`. Композит =
   произведение двух матриц: после открытия из миниатюры картинка 1600×900
   рисовалась прямоугольником 144×81 вместо 480×270 (замер: imgRect
   `{x:168, y:625, w:144, h:81}`).
2. **Хит-зоны кропа в пикселях источника.** `HANDLE_SLOP = 28` сравнивался с
   координатами картинки: на изображении 3000×2000 угол захватывался в
   **2.1 экранного пикселя** (замер `cornerGrabScreenPx`), палец не брал.
3. **Кадр без явного размера.** `.uris-viewer-img` не имел CSS-ширины: при
   подмене миниатюры (WebP ≤512px) полным файлом геометрия прыгала, math
   считал от габаритов полного файла, а layout — от миниатюры.
4. **Мгновенная смена слайдов** вместо карусели, свайп только по 30% ширины,
   без инерции; щипок не клампился (кадр улетал за край до конца жеста);
   после pinch→один палец пан считался от устаревшей базы.
5. **Мёртвые ручные стенды.** `lightbox.js` звал `getCtx()` →
   `SillyTavern.getContext()` — на страницах без ST кнопка молча падала
   (`ReferenceError`), регрессии не ловились вовсе.
6. Кроп: 4 угла без рёбер, без рисования новой рамки, без зума для точности,
   ratio-ресайз терял якорь, paint дёргал layout на каждое движение.

## Решение

Собственное, без вендоров (Croppr/PhotoSwipe удалены ранее), по правилам
Cropper.js (кроп) и PhotoSwipe v5 (просмотрщик). Ядра — чистые модули без DOM
под `node --test`, контроллеры — тонкие адаптеры.

### Ядра (чистые, детерминированные)

- `src/ui/crop-math.js` — рамка в пикселях источника; 8 маркеров (углы
  приоритетнее рёбер); угол держит противоположный (якорь), ребро ре-центрирует
  поперечную ось; свободная рамка переворачивается при протаскивании через
  якорь; смена пресета вписывает рамку вокруг её центра; `newCrop` — рисование
  с двух точек; `roundEdges` — округление по кромкам (Cropper #343); минимум
  стороны приходит ИЗВНЕ (адаптер считает 44 экранных px).
- `src/ui/gesture-math.js` — тап/двойной тап (300мс/25px), пан, щипок вокруг
  центроида, бросок (окно ~80мс, порог 0.5px/мс); щипок разрывает серию тапов;
  `cancel()` для pointercancel; после pinchend origin переезжает на
  оставшийся палец.
- `src/ui/viewer-math.js` — fit/centered/zoomAt (зум к точке = формула щипка
  PhotoSwipe), clampPan, `rubberPan` (демпфер 0.35 за краем), `rubberZoom`
  (0.15 ниже минимума, 0.05 выше максимума), `flipFromRect`/`rectFromTransform`
  (FLIP), `slideOffset` (зазор 10%), `stepSpring` (пружина ω0/ζ,
  перенацеливается на лету), `springSettled` (<1px и <50px/с), `stepDecay`/
  `projectedStop` (затухание 0.995/мс).

### Просмотрщик `src/ui/lightbox.js`

- Карусель из **трёх слайдов** (prev/cur/next), позиции — translate3d со
  сдвигом 110% ширины кадра; соседи прячутся, src меняется по месту.
- Один transform-таргет: анимации и жесты пишут transform **самой картинки**;
  FLIP открытия/закрытия — WAAPI на img (333мс, `cubic-bezier(.4,0,.22,1)`,
  от прямоугольника миниатюры через `flipFromRect`); перехват анимации —
  чтение computed-матрицы (DOMMatrix) и cancel.
- Картинка несёт **явные CSS-ширину/высоту** натуральных размеров: подмена
  миниатюры полным файлом не двигает геометрию.
- Жесты: осевой гистерезис 10px (горизонталь — лента, вертикаль — закрытие с
  трением 0.6 и гашением фона к 1/3 высоты); навигация — бросок ≥0.5px/мс или
  полкадра; закрытие — проекция броска ≥0.4 от (высота/3); щипок с резиной за
  границами зума; двойной тап — 2.5× (крупные кадры — не выше 100%); колесо —
  зум к курсору; тап — тогл тулбара; стрелки, +/−, Esc; Tab не выпускает фокус.
- Пружины: одна анимация за раз (поколение), обрыв без потери значений
  (state в замыканиях контроллера).
- Контракты прежнего поведения сохранены: закрытие синхронно снимает корень с
  hit-теста (pointerEvents+inert), копирование/референсы не закрывают просмотр,
  фокус возвращается к триггеру.

### Кроп `src/ui/crop-dialog.js`

Контракт `openCropDialog({source, allowSkip, presets})` и `CROP_PRESETS`
не изменены. Внутри:

- Захват маркера — **24 экранных px** (minImagePx для минимума рамки — 44),
  перевод в пиксели картинки на каждом жесте.
- 8 маркеров (визуально: углы-квадраты, рёбра-полоски), сетка третей во время
  тяги, затемнение — 4 шторки (позиции пишутся в том же rAF-батче).
- Рисование новой рамки протягиванием снаружи (после 8px — тап не сбрасывает);
  на зуме перетас вне рамки панорамирует стадию.
- Зум стадии: колесо ±10%/нотч к курсору (тротлинг как у Cropper), щипок
  вокруг центроида, диапазон 1..4×; canvas-слой с transform-origin 0 0.
- Клавиатура: стрелки — перенос (Shift — ×4), Alt+стрелки — размер, Enter,
  Esc; фокус в диалоге на открытии, возврат к триггеру, Tab-ловушка.

### Инфраструктура

- `src/ui/scroll-lock.js` — scroll-lock без зависимостей (выведен из
  `window.js`, который ре-экспортирует старые имена): просмотрщик и кроп не
  тянут цепочку до core.js.
- `core.tryGetCtx()` — контекст, которого может не быть: на стендах chatId
  становится null вместо ReferenceError.
- Ручные стенды: `tests/manual/viewer-harness.html` (карточки с миниатюрами —
  FLIP, кроп 600×400 и 3000×2000) и `tests/manual/lightbox-mobile.html`
  (карусель из трёх кадров) — работают **без SillyTavern**.

## Что сознательно НЕ делаем (YAGNI)

- react-easy-crop-модель «рамка стоит, картинка ездит» для фиксированных
  соотношений — одна модель (рамка) покрывает оба режима; вторая удваивает
  поверхность жестов.
- Поворот кропа, perspective, batch-анкеры — не нужны сценариям расширения.
- Виртуализация дальше трёх слайдов, srcset, percent-контракт кропа.
