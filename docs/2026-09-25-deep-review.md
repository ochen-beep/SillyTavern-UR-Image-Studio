## 0. Вердикт

**Идея: 8/10. Исполнение: 7.5/10.**

Идея — «нарисовать момент чата, не испортив текст, с лицом персонажа и без сюрприза 1:1 вместо 16:9» — настоящая и подтверждена рынком: у QIG двухшаговый пайплайн сцены появился именно потому, что это то, чего хотят RP-пользователи. Уникальная связка URIS, которой нет у конкурентов в сборе: пул референсов с папками и привязкой к чату, явные диалекты шлюзов (OpenRouter `image_config` vs new-api `extra_body`) с проверкой реальных пикселей против запрошенного аспекта, галерея в родном хранилище ST вместо IndexedDB, внешний мост `globalThis.URIS` для других расширений, честная семантика «оплаченный POST не пересылаем вслепую».

Исполнение для соло-альфы выше среднего: сентябрьское ревью не осталось приговором — волны 0.9.1–0.9.6 закрыли мёртвую серверную линию, двойной биллинг, утечку промптов через дамп и половину дедупликации. До беты режут не код, а **плотность интерфейса** (7 дропдаунов в главном сценарии, окно поверх чата без Esc) и **отсутствие онбординга**: ближайший конкурент даёт первый кадр из мастера за минуту.

Главные живые риски: окно можно потерять без Esc и без пересчёта геометрии на scroll; черновики растут в IndexedDB вечно; ретрай платного текстового запроса срабатывает по подстроке «429» в любом месте сообщения; глобальный мост включён всегда.

## 2. Критичные находки (живые)

### 2.1. Окно можно потерять: Esc, кламп на scroll, touch-ресайз
- **Esc не закрывает главное окно.** Единственный обработчик Escape — панель ошибок (`window.js:347-353`). У самого окна нет ни Esc, ни клика по фону; единственный выход — «Свернуть». Воспроизведено в UI-аудите 2026-09-15 (п. 2.2) — с тех пор не чинено.
- **Геометрия клэмпится только при восстановлении** (`restoreGeometry`, window.js:204-217). ST ставит на `<html>` identity-transform, что делает `<html>` содержащим блоком для `position:fixed` — при `scrollY ≠ 0` окно уезжает вместе со страницей, и шапка с кнопками может уйти за вьюпорт. `initViewportSync` (window.js:186-198) обрабатывает только `resize` ради мобильного класса — кламп на scroll/resize не пересчитывается.
- **Ресайз только мышь:** ресайзер слушает `mousedown` (window.js:241); drag шапки — ручные mouse+touch с `passive: true` (window.js:238-241, 390), на таче страница скроллится под пальцем, ресайза нет вовсе. Эталон уже в кодовой базе — `floating-launcher` на Pointer Events.

**Фикс (день работы):** Esc при фокусе внутри окна → свернуть; rAF-throttled кламп на `scroll`+`resize`; ресайзер и drag на Pointer Events.

### 2.2. Черновики растут вечно
`uris_generation_draft:<chatId>:<msgId>` пишется на каждый пост (`generation-drafts.js:353-356`) и не удаляется никогда. `sweepStaleRunningDrafts` (generation-drafts.js:367-392) только откатывает зависший `running → idle`; ключи не перечисляет на предмет чистки. Каждый пост каждого чата оставляет запись со снапшотами в IndexedDB навсегда. **Фикс:** в свип — TTL (например, 30 дней) или потолок «N последних постов на чат».

### 2.3. refreshActive съедает ввод
`uris:post-follow` и `chat-generation-defaults-changed` дергают полный `refreshActive()` вкладки «Генерация» (index.js:224-228, 187, 193), а тот пересобирает `body.innerHTML` (tabs.js:53). Если пользователь печатает в промпте (автосейв с debounce 400 мс), textarea пересобирается со старым драфтом — правка и фокус теряются. **Фикс:** не рендерить при фокусе в `#urisPrompt` либо синхронно сливать значение в драфт перед ререндером.

### 2.4. Тихий глотатель рендера вкладки + ретрай по подстроке
- `tabs.js:69` — упавший async-рендер глотается `catch(() => {})`: пользователь видит пустую вкладку, в пул ошибок ничего не падает. **Фикс:** `catch(e => recordUrisError({ scope: 'UI', message: ... }))`.
- `core.js:637` — ретрай платного текстового запроса по regex `/429|502|503|504|network|Failed to fetch|CORS/i` по **тексту** ошибки: «429» в любом месте сообщения шлюза триггерит повтор. Для POST с исходом-неизвестностью защита есть (`noRetry`, core.js:627-632), но статусная семантика надёжнее текстовой. **Фикс:** ретрай только по `httpStatus` ∈ {429, 502, 503, 504} и типизированным кодам; текст оставить в логе. (Image-transport уже правильный — ретрая у картинок нет.)

### 2.5. CHANGELOG ↔ код: `apiKeyState` не на `serialize()`
CHANGELOG волны 1 (0.9.4) заявляет «цепочка `apiKeyState` в core.js заменена на `serialize('uris-api-key')`». В коде — прежняя ручная цепочка `apiKeyState.chain` (core.js:664-685). `serialize.js` переведены connection-evidence, browser-image-recovery, generation-drafts, autolane — core.js нет. Гонка записи ключа по-прежнему держится на ревизионной гвардии, которая работает только благодаря цепочке. **Фикс:** перевести на `serialize()` либо поправить CHANGELOG.

### 2.6. Evidence-диалект может закрепить неудачный маршрут
`dispatch-plan.js:208-214` берёт `connection.evidence[modelId].dialect` для следующей генерации. Классификатор отказов шлюзов работает по английским текстам чужих гейтвеев (`capability-observer.js`); одна misclassификация способна закрепить нерабочий диалект для соединения. Оговорка «diagnostic-only» уже неточна. **Фикс:** понижать evidence только после повторного противоречащего факта, либо хранить «последний рабочий» отдельно и возвращаться к нему после N неудач.

### 2.7. Мост включён всегда — решение не принято
`activateBridge()` публикует `globalThis.URIS` до загрузки настроек (index.js:103), безусловно. За настройкой `bridgeTab === true` спрятана только вкладка (index.js:135). Любой скрипт той же страницы (другое расширение, инжект темы) может вызвать `URIS.generate` и потратить деньги пользователя. Для страницы SillyTavern это не XSS, но это **внешняя поверхность траты денег без opt-in**. **Решение (продуктовое):** публиковать глобал только при `settings.bridgeEnabled === true` (по умолчанию off) с явным тумблером, либо оставить как есть и громко задокументировать «мост доверяет всем скриптам страницы». Нынешнее состояние — худшее из двух: таб спрятан, а поверхность открыта.

### 2.8. Мелочи
- `chat-binding.js:151-178`: легаси-запись кладётся под `legacy`, следующая нормализация её снова выбрасывает — полумёртвая ветка.
- В дереве репозитория лежат логи прогонов (`.tmp-test.log` 156 КБ, `baseline-tests.log` 122 КБ и др.) — gitignore их покрывает, но перед публикацией пакета/репо стоит удалить физически.
- `pipeline-stage2.js:411` — `catch (_) {}` при записи ошибки в драфт: второй тихий глотатель в горячем пути (менее критичен, чем вкладки).

## 3. Архитектура: что оставить и что осталось

### 3.1. Транспорт — эталон, не трогать
`autoFetch` (proxy.js:238-281): POST при CORS-маскированном сбое не пересылается — `DELIVERY_AMBIGUOUS` + флип хоста в 'proxy'; GET-фолбэк сохранён для идемпотентных запросов. `probeDeliveryStrategy` (proxy.js:305+) делает дешёвый GET до первого платного POST. `image-transport` держит `noResubmit` и `IMAGE_DELIVERY_AMBIGUOUS`. Эта семантика у QIG появилась только в 3.5.0 — здесь она старше и чище. Таймаут не ретраится нигде (core.js:617-632) — правильно.

### 3.2. Хранение
- `file-store.js` (987) — правильный ответ на «ST перезаливает settings.json целиком». Секреты не экспортируются (data-port.js:352 режет `apiKey/token/password/secret`).
- `mergeWithServer` (трёхсторонний merge) включён **только у refs** (refs-library.js:61); студия и остальные — last-writer-wins (studio-scope.js:54). Для двух вкладок одного браузера это окно потери; документированный инцидент уже был (file-store.js:44-55). Решение то же, что в 09-22: либо merge всем одной конфиг-строкой, либо честный single-writer.
- Бойлерплейт магазинов (5 × по 15+ однострочных ensure/flush/replace; ручные списки в index.js:120-126 и flush-перечислениях) — фабрика `defineStore` по-прежнему напрашивается (−300…400 строк).
- `addToGallery` теперь материализует картинку до индексации одним `addCard` (storage.js:57-91) — старая находка про 3 перезаписи на картинку требует перепроверки, но `updateGalleryEntry` (storage.js:176-181) остаётся отдельной записью на каждый патч.

### 3.3. UI
- Модель «innerHTML на мутацию + точечные хосты ввода» здорова; vdom не нужен. Дисциплина `escapeHtml` ручная: ~88 присваиваний innerHTML против ~173 вызовов escapeHtml; по аудиту 09-22 пользовательские и LLM-данные экранированы, реальных XSS нет. Риск процессный: один пропущенный `${name}` — XSS внутри ST. Дешёвая страховка — grep-тест «интерполяция внутри innerHTML без escapeHtml на строке» падает.
- Вкладки без ARIA-ролей: `renderTabs` (tabs.js:79-93) строит кнопки без `role="tab"/"aria-selected"`, стрелки не переключают — P0 из аудита 09-15, не закрыто.
- Три реализации drag (launcher на Pointer Events — эталон; окно на mouse+touch; чипы) — один pointer-хелпер, −80 строк и чинит п. 2.1.
- Модалки: фокус-трапа нет, Esc закрыт не везде (аудит 09-15 п. 2.7) — общий `openUrisDialog()` всё ещё актуален.

### 3.4. Диагностика и инлайн
Не трогать: netdump v2 (metadata-only), diagnostic-events, error-pool с quiet-записями (0.9.6), grammar.js (ReDoS-безопасен), render.js (план-реконсиляция + textContent), autolane.

### 3.5. Вендоры
PhotoSwipe — ядро UX, оставить. Croppr (1 182 строки на один диалог) — кандидат на замену собственным прямоугольником поверх общего drag-хелпера (~150-200 строк), если кроп не ежедневный жест.

### 3.6. Стек
Чистый ESM без бандлера, `node --test`, свой `fake-dom` — оптимум для расширения ST; React/Vite были бы налогом. Обновление до будущих версий ST держится на пробах с деградацией — нормально.

## 4. Продукт

**Value proposition** — см. вердикт. Ценность подтверждается тем, что каждый конкурент вынужден решать те же проблемы (двухшаговый промпт у QIG, референсы у SLAY), но никто не собрал их с сохранением чата нетронутым и с галереей в родном хранилище.

**Блокеры беты (не фичи, а первый успешный кадр):**
1. **Онбординг:** мастер «провайдер → ключ → Проверить → один кадр с последнего поста». Сейчас установка заканчивается чтением USER_GUIDE и ручной сборкой соединения на вкладке API.
2. **Окно:** Esc + гарантия видимой шапки (2.1). Потерянное окно = потерянный пользователь.
3. **Прогресс:** генерация 10-60 с — по NN/g нужен percent-done: полоса фаз «Шаг 1 → Шаг 2 → Сохранение», время, скелетон в галерее. Сейчас пульс FAB и текст в шапке.
4. **Плотность «Генерации»:** 7 дропдаунов подряд; редкие (модель/шаблон/автоматизация/флоу) — в сворачиваемый блок «Параметры»; на мобиле кнопка генерации sticky внизу.
5. **Галерея:** 1 колонка на телефоне → 2; 5 иконок на карточке → действия в лайтбоксе + «⋯»; массовое удаление (индекс расходится с экраном — пользователь не может почистить 716 скрытых записей); Undo вместо confirm на мягком удалении.

**Не делать в бете:** видео, Comfy/A1111-графы, гардероб, новые провайдеры, мост-платформа. Это всё чужие поля, где конкуренты уже вложились больше.

## 6. Куда расти (tech-vision)

Не «ещё одна модель», а удешевление и стабилизация уже оплаченного кадра:
1. **Дешёвый профиль только для Stage 1** (отдельно от чата) — QIG и Tag-Pilot продают именно это; у URIS Connection Manager-профиль уже технически поддержан, не хватает UI-нарратива.
2. **Классификация исхода по HTTP-статусу**, не по английскому тексту шлюза (2.4, 2.6) — это и надёжность, и фундамент для авто-диагностики соединений.
3. **Evidence-стор как память удачных связок** «коннект × модель → диалект» (с оговоркой 2.6 — не давать одному кривому отказу переписать рабочий маршрут).
4. **Мост как контракт для одного потребителя** (прогон с Offstage уже был): стабильный `classifyError` + `listPending` из 0.9.6 — правильный объём; решить вопрос opt-in (2.7).
5. Если когда-нибудь «гардероб» — не вторая подсистема, а один слот «одежда этого чата» поверх существующего пула референсов.
