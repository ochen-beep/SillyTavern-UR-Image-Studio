# План: автоматика на RENDERED-событиях, коалесцирующий слот и фингерпринт-пропуск

Дата: 2026-10-26 · Статус: план · Источник паттернов: SillyTavern-DS-Comments
(`src/events.js`, `src/generator.js` там) · Анализ дыр: разбор 2026-10-26
(событийная автоматика без сериализации, двойные вкладки, свайп-спам).

---

## 1. Цель

Событийная автоматика («Строить промпт» / «Полный pipeline» по новым постам)
должна: не тратить параллельно, не тратить повторно на уже обработанный
контент, не стрелять в чужой/устаревший чат. Без изменений ручного запуска,
пачечной очереди и автолейна моста/инлайна.

## 2. Проверенные факты стека (ST, чекаут D:\SillyTavern QA)

1. `event_types.CHARACTER_MESSAGE_RENDERED` / `USER_MESSAGE_RENDERED`
   существуют; контекст отдаёт оба алиаса (`event_types` и `eventTypes`,
   st-context.js:139/223) — наш стиль `event_types` сохраняется.
2. `CHARACTER_MESSAGE_RENDERED` стреляет ровно один раз на новое AI-сообщение:
   после DOM-рендера, с актуальным `swipe_id`; при стриминге — один раз на
   завершении (`finalizeIntermediaryMessage`, script.js:3800/3829);
   `type: 'impersonate'` — не стреляет (script.js:3801: guard).
3. **Навигация по существующим свайпам НЕ стреляет RENDERED** — только
   `MESSAGE_SWIPED` (script.js:10293/10315). Новый вариант свайпа (генерация
   за правым краем) — RENDERED. То есть «свайп назад» бесплатен уже по
   семантике события; кэш нужен как страховка и для будущих фич.
4. `USER_MESSAGE_RENDERED` — при отправке поста юзера (script.js:5912/5919),
   до ответа AI. В потоке «all» это два запуска на обмен репликами — как
   сегодня (MESSAGE_SENT + GENERATION_ENDED), но сериализованно (§3.Б).
5. Загрузка чата (`printMessages`) НЕ стреляет RENDERED — открытие чата
   автоматику не запускает (паритет с сегодняшним GENERATION_ENDED).
6. Наши драфты ключуются `(chatId, msgId)`; смена текста поста (свайп)
   сбрасывает драфт (`generation-drafts.js:182-200`, messageHash). Ключ не
   меняем (миграция — отдельная фаза, см. §6 «не делаем»).
7. Существующий дедуп `autoFlights` (pipeline-stage1.js:221-240) живёт только
   вокруг full-pipeline, только пока запрос в полёте, ключ — хэш текста:
   параллельные платные POST разных постов не предотвращает.
8. `events.js` уже имеет `_chatLoadToken` (бампается на CHAT_CHANGED) и
   `state.currentChatId` — эпоховый гвард строится на них, новой механики
   инвалидности не нужно.

## 3. Дизайн

### А. Триггеры (events.js)

- Автоматика пересаживается на `CHARACTER_MESSAGE_RENDERED` (AI-посты) и
  `USER_MESSAGE_RENDERED` (посты юзера, только при потоке `user-only`/`all`).
- Подписки автоматики на `GENERATION_ENDED`/`MESSAGE_SENT` удаляются.
  Навигатор (post-follow) остаётся на GENERATION_ENDED/MESSAGE_SENT/MESSAGE_SWIPED
  без изменений — он не тратит и жалоб на него нет.
- `triggerIfMatches` сохраняет фильтры потока, `isGenerationEligible`, ретрай
  пустого chatId (на RENDERED пустого chatId практически не бывает — ретрай
  остаётся дешёвой страховкой). Новое: читаем `swipeIdx` из сообщения и
  передаём в payload.
- Новый guard: пропускаем `msg.extra?.uris_auto_consumed`?? — нет, см. §3.В:
  пропуск по фингерпринту, без записи в чат.

### Б. Однослотовая коалесцирующая очередь (events.js, ~25 строк)

```
let _autoRunning = false;
let _autoParked = null;   // последняя задача побеждает
```
- Триггер: если `_autoRunning` → `_autoParked = payload; return`.
- Иначе `_autoRunning = true`, прогон `_onAutomation(payload)`, в `finally`:
  `_autoRunning = false; if (_autoParked && chatToken актуален) { const p = _autoParked; _autoParked = null; запустить p; }`.
- CHAT_CHANGED (тот же обработчик, что бампает `_chatLoadToken`) сбрасывает
  `_autoParked = null` — припаркованное в новый чат не перетекает.
- Эпоха: payload несёт `chatId` + `chatLoadToken` на момент события; перед
  запуском и после каждого await сверяем — расхождение → тихий выход.
  (Закрывает гонку ретрая chatId и смену чата в полёте на уровне диспетча;
  внутрипайплайновые гварды драфтов/run-token'ов остаются как есть.)

Это заменяет автолейн для событийного пути: FIFO автолейна копит платные
задачи, слот — нет. Автолейн моста/инлайна не трогаем (там задачи равноправны
и пользовательские).

### В. Фингерпринт-пропуск (pipeline-stage1.js + generation-drafts.js)

- Драфт получает два поля: `autoPromptFp` (записывается при успешном apply
  Stage 1 в авто-режиме) и `autoDoneFp` (при успешном Stage 2 в авто-режиме).
  Ручные запуски и очередь эти поля не пишут и не читают.
- fp = fnv1aHex(`${msgText}|${effectiveTemplateId ?? 'base'}|${connectionId ?? ''}|${modelId ?? ''}|${aspectRatio}|${imageSize}|${quality}`) —
  собирается в runStage1ForDraft после резолва snapshot'а (все входы там есть).
- В начале авто-прогона:
  - режим «Строить промпт»: если `draft.autoPromptFp === fp` и `draft.prompt`
    непуст → `{ applied: false, reason: 'auto-fingerprint-match' }`, бесплатно.
  - «Полный pipeline»: то же, но по `autoGenDoneFp` (свайп назад к готовой
    картинке — бесплатно; свайп к варианту с промптом без картинки — докрутит
    Stage 2: намеренно).
- Это покрывает и regenerate-повторы: тот же текст+настройки → пропуск;
  изменил настройки/шаблон/модель → перегенерация (как у DS Comments, где fp
  включает настройки).

### Г. Тесты

- `tests/events.test.js` переписать под новые события: те же кейсы потоков
  (ai-only/user-only/all/manual) на RENDERED-событиях; + свайп-навигация не
  триггерит (MESSAGE_SWIPED без RENDERED); + слот (два быстрых события → один
  прогон + parked; припаркованный дренится после finally; CHAT_CHANGED его
  выбрасывает); + устаревший chatToken → тихий выход.
- Новый тест: `autoPromptFp/autoDoneFp` — повторный авто-запуск с тем же fp
  пропускается; смена модели — не пропускается; ручной запуск fp не пишет
  и не читает.

## 5. Критерии готовности

- npm test зелёный; событийный автопрогон: одна генерация на сообщение,
  параллельных платных POST нет (видно по сетевому дампу), свайп назад не
  тратит, impersonate не тратит, быстрая пара «юзер→AI» сериализована.
- Ручной запуск/очередь/мост/инлайн работают как раньше (регресс-тесты есть).

## 6. Не делаем сейчас

- Пересветку драфтов на ключи `(chatId, msgId, swipeIdx)` — миграция хранилища
  и всех читателей; текущий fp-пропуск даёт 90% выгоды без неё. Отдельной
  фазой, если захочется «у каждого свайпа свой промпт».
- Гард двух вкладок (события стреляют в обеих) — ортогональный микрофикс
  (`lockState === 'busy'` → не биндить автоматику), отдельным коммитом.
- Студийный чат: добавить явный гвард `isStudioChat` в триггер, если
  ручная проверка покажет срабатывание (сегодня не доказано).
