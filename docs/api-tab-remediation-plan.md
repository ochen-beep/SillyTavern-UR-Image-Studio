поэтому регекс по имени модели для выбора *параметра* остаётся уместным; для
выбора *протокола* — нет.

### 1.2 Наблюдатель свёрнут до логгера

`capabilityObservations` персистились в маршрут подключения, но читались только
из тестов: у `getCapabilityProfile` не было ни одного продового вызова.

Автоматизация здесь и не могла дать пользы. Подтверждение возможности требует
платной попытки, то есть автомат способен лишь запомнить то, что пользователь
уже сделал и уже знает. Подключений мало, протокол прокси статичен. А если
позволить наблюдениям переопределять поле карточки, карточка начнёт молча
расходиться с фактическим поведением — тот же класс дефекта, что скрытая цепочка
фолбэков в `sillyimages`.

Итог: убраны персист, `buildObservation`, `getCapabilityProfile`,
`extractUnsupportedHint`; из схемы убрана нормализация наблюдений, добавлена
очистка легаси-поля. Осталась одна человекочитаемая строка лога. Тесты
конвейера переориентированы с чтения хранилища на перехват `console.log` —
лог теперь и есть вся наблюдаемая поверхность.

Инвариант сохранён: сетевой сбой логируется как `network-unknown` и **никогда**
как `unsupported`. Платный POST не переотправляется автоматически.

## 2. Сверка с SillyTavern

### 2.1 Подтверждено корректным

**`POST /api/images/upload`.** Поля совпадают с хелпером `saveBase64AsFile`
(`public/scripts/utils.js`): `image` (base64 без data-URI префикса), `format`
(расширение без точки), `ch_name` (подпапка — именно это имя поля, не
`subfolder`), `filename`. Ответ — `{path}`. Лимит тела глобальный,
`bodyParser.json({ limit: '500mb' })`, упереться в него практически нереально.

**CSRF.** Защита `csrf-sync` включена глобально, токен читается из заголовка
`x-csrf-token`. Исключение одно — `/proxy/*`, и только при включённом прокси.
`src/references.js:253` и `src/native-image-storage.js:17` берут заголовки из
`getRequestHeaders()`, токен на месте.

**Прокси.** Путь `/proxy/<url>` в `src/proxy.js:38` верный: маршрут ST —
`/proxy/:url(*)`, целевой URL живёт в пути, не в теле. Вывод «прокси только
JSON» подтверждён построчно: `body: JSON.stringify(req.body)`. Явный отказ
multipart в `canProxyJsonRequest` — обоснованное поведение, не перестраховка.
Middleware не вычищает `authorization`, так что ключ через прокси доходит.
Прокси выключен по умолчанию (`enableCorsProxy: false`).

**Запись в чат.** URIS не пишет изображения в сообщения чата вообще —
`extra.media` в коде не встречается. Переход ST с одиночного `extra.image` на
массив `extra.media` проекта не касается.

### 2.2 Три расхождения

**Р1. `format` из MIME может быть отвергнут сервером.**
`src/references.js:244` делает `mime.replace('image/', '')`. Белый список ST
(`MEDIA_EXTENSIONS` в `src/constants.js`) содержит и `jpeg`, и `jpg` — типовой
случай проходит. Но `image/svg+xml` даёт `svg+xml`, `image/avif` даёт `avif`;
ни того, ни другого в списке нет, и ST отвечает 400 `Invalid image format`, а не
подставляет дефолт. Сравнение регистрозависимое, `PNG` отвергается.
`src/native-image-storage.js:41` то же самое уже делает правильно — regex по
белому списку с нормализацией `jpeg → jpg`. То есть два пути загрузки в одном
проекте расходятся в поведении.

**Р2. Точки в имени файла.**
Хелпер ST заменяет `.` на `_` перед отправкой, а серверный
`removeFileExtension()` срезает последний сегмент после точки.
`src/references.js:246` убирает `..`, слэши и пробелы, но одиночные точки
оставляет: `ref.v2` уедет как `ref.png` с потерей `v2`.
`src/native-image-storage.js:34` снова корректен.

**Р3. Путь из ответа не канонизируется.**
ST возвращает сырой путь, без percent-encoding, с пробелами из имени папки:
`user/images/UR Image Studio/x.png`. `uploadReferenceImage` возвращает
`result.path` как есть, минуя `canonicalizeNativeImagePath`. Для `URIS_Refs`
без пробелов безобидно; для `ch_name` = имя персонажа с пробелом путь попадает
в разметку неэкранированным.

Уточнений по документации ST не требуется — все три расхождения проверяемы по
исходникам и однозначны.

## 3. Открытые дефекты

Помимо трёх расхождений с ST, review нашёл следующее.

**Д1. `editProtocol` недостижим из UI.** Поле работает в схеме и в провайдере,
но в `src/ui/server-connection-form.js` его нет. Выставить протокол без правки
persisted-данных невозможно — то есть починенный механизм пользователю
недоступен.

**Д2. `manualModelId` теряется при перезагрузке.** Собирается в
`collectServerConnectionForm` (строка 129), но в `collectSavePayload`
(строки 137-146) не попадает.

**Д3. `escapeHtml` сломан.** `src/ui/server-connection-form.js:19`: `>`
заменяется на `&quot;` вместо `&gt;`, а кавычки не экранируются вовсе. Функция
при этом подставляется в значения атрибутов (`value="${escapeHtml(...)}"`) —
имя коннекта с кавычкой ломает разметку.

**Д4. `uploadEntryAsRef`**: форма возврата не приведена к остальным путям,
изображение не прогоняется через `optimizeReferenceImage`.

**Д5. Сообщение об ошибке референса** показывает внутренний id вместо имени и
пути — по нему нельзя понять, какой именно референс отвалился.

**Д6. `src/image-recovery.js` — НЕ мёртвый код.**
Исследование показало: модуль живой. `executionOwner === 'server'` — легальный
вариант соединения (`connection-store.js`), `server-image-api.js` экспортирует
`generateServerImage`, а `image-recovery.js:217` вызывает именно его для relay-пути.
В `tests/server-stage2-recovery.test.js` — 12 зелёных тестов, использующих модуль.
Единственный перекрёстный импорт в non-server тестах (`tests/image-api-server.test.js`)
заменён на `listPendingBrowserRequests` из `browser-image-recovery.js`.
Удаление отменилось. Позитивная интерпретация: server-relay инфраструктура в сборе
и протестирована, готова к подключению server-соединений через UI.

### Отложено, требует отдельного решения

- `unsupportedParameters` записывается, но при сериализации тела не
  учитывается.
- Один `bodyKind` на маршрут не выражает «JSON для generate + multipart для
  edit». Честный вариант — разделить `route.operations.generate` и
  `route.operations.edit`.
- `ReferenceError: t is not defined` в `buildPanel` (`src/window.js:373`) при
  `CHAT_CHANGED` — к вкладке API отношения не имеет, но воспроизводится.
- Архитектурный вопрос: достаточно ли одного метода отправки, или несколько
  протоколов на подключение — единственный честный ответ.

## 4. План реализации

Порядок — по риску: от «ломает генерацию» к косметике. После каждого шага
прогон набора без `server-*`; шаг не считается закрытым, пока набор не зелёный.

### Шаг 1. Единый нормализатор `format` и `filename`

Закрывает Р1 и Р2 сразу и убирает дублирование.

Вынести белый список расширений ST и санитайзер имени в отдельный модуль
(`src/st-upload-format.js`), взяв за образец уже корректные
`src/native-image-storage.js:34` и `:41`. Экспорт: `formatForMime(mime)` и
`sanitizeUploadFilename(name)`.

- Список расширений привести к `MEDIA_EXTENSIONS` ST, сравнение — в нижнем
  регистре, `jpeg → jpg`.
- Неизвестный MIME — явная ошибка **до** сетевого вызова, с указанием
  полученного MIME. Не 400 от сервера и не молчаливый `png`.
- Точки в имени заменять на `_`, как это делает `saveBase64AsFile`.

Подключить в `src/references.js:244-250`, а `native-image-storage.js` перевести
на общий модуль, чтобы не осталось двух реализаций.

Тесты: неизвестный MIME (`image/avif`, `image/svg+xml`) отвергается до `fetch`;
`image/jpeg → jpg`; `PNG` в верхнем регистре нормализуется; `ref.v2` не теряет
`v2`.

### Шаг 2. Канонизация пути из ответа

Закрывает Р3. `uploadReferenceImage` возвращает
`canonicalizeNativeImagePath(result.path)`. Если функция вернула `null` —
ошибка, в сообщении привести исходный путь. Проверить, что вызывающие
(`src/ui/tab-references.js:35`, `src/ui/gallery-actions.js:138`,
`src/server-store-api.js:20`, `localizeRemoteReference`) не кодируют путь
повторно.

Тест: путь с пробелом в имени папки возвращается закодированным ровно один раз.

### Шаг 3. `escapeHtml` + `editProtocol` в карточку

Делать вместе: селект добавляет ещё одно место, где значение уходит в атрибут,
поэтому экранирование правим первым в рамках того же шага.

Сначала `src/ui/server-connection-form.js:19` — `>` → `&gt;`, добавить `"` →
`&quot;` и `'` → `&#39;`.

Затем `editProtocol` (закрывает Д1): селект рядом с CORS-чекбоксом
(строка 93), два значения — `multipart` (по умолчанию) и `json`. В `title`
описать признаки в тексте ошибки провайдера, по которым выбирают вариант:
упоминание `image` против `images`, явные упоминания multipart. Добавить поле в
`collectServerConnectionForm` (возврат, строки 120-134) и в
`collectSavePayload` (строки 137-146) — иначе значение не доедет до хранилища.

Тесты: значение переживает round-trip форма → сохранение → рендер; дефолт
`multipart` при отсутствии поля; имя коннекта с кавычкой не ломает разметку.

### Шаг 4. `manualModelId` в `collectSavePayload`

Закрывает Д2, правка в одну строку. Тест: введённый вручную ID модели
сохраняется и виден после перезагрузки карточки.

### Шаг 5. `uploadEntryAsRef`

Закрывает Д4: привести форму возврата к остальным путям загрузки, прогнать
изображение через `optimizeReferenceImage`, использовать нормализатор из шага 1.

### Шаг 6. Сообщение об ошибке референса

Закрывает Д5: в тексте ошибки имя и путь вместо внутреннего id.

### Шаг 7. ~~Удалить `src/image-recovery.js`~~ → Отменено

Исследование выявило, что premise Д6 неверный: `image-recovery.js` не мёртвый код.
Модуль обслуживает server-relay путь (`executionOwner === 'server'`), который

## 5. Инварианты, которые нельзя нарушить

Действуют на всех шагах.

- Платный POST к провайдеру **никогда** не переотправляется автоматически.
  Таймаут, разрыв и неоднозначный 5xx не доказывают, что списания не было.
- Протокол не выясняется серией платных POST. Пробы считать платными и
  требовать явного согласия.
- Сетевой сбой не записывается как `unsupported`; `unknown` не сворачивается в
  `unsupported`.
- Ключ провайдера не уходит в браузерный JS ни в каком серверном relay-дизайне.
- Любой relay изображений: allowlist http/https, блокировка localhost и
  приватных сетей (SSRF), отказ от редиректов в приватные сети, лимит размера,
  проверка MIME, таймауты, редактирование auth-заголовков в логах.
- Карточка соединения — источник истины. Ничто не переопределяет её молча.
