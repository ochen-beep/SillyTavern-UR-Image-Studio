# План ручного тестирования UR Image Studio

Тестовый стенд: SillyTavern на `http://127.0.0.1:8001/`, пользователь `default-user`, расширение из `data/default-user/extensions/UR Image Studio`.

Дата: 2026-10-20 · Версия: 0.9.8

---

## 0. Подготовка стенда

1. ST 1.19.x запущен на 127.0.0.1:8001, расширение включено в **Manage Extensions**, без ошибок установки.
2. `config.yaml`: `enableCorsProxy: true` — нужен для блока «Доставка через прокси»; до включения пометить соответствующие кейсы.
3. Открыть DevTools (F12), вкладка Console — ошибки фиксируются по каждому блоку. Пустая консоль = пререквизит «чистого» прогона.
4. Подготовить:
   - тестового персонажа и чат с 10–15 постами (есть реплики персонажа и юзера);
   - пустой чат и welcome-экран (для кейсов «нет контекста»);
   - 5–8 тестовых картинок на диске (разные пропорции, включая вертикальную и очень широкую);
   - хотя бы одно рабочее текстовое подключение (профиль Connection Manager) и одно картинное подключение с реальным ключом. Если платных ключей нет — блок генерации прогоняется на Pollinations/Cloudflare free-tier, остальное мокается проверками UI.
5. Сделать «снимок» чистого состояния: скопировать папку расширения и (при желании) `data/default-user` — для возврата между блоками.

## 1. Smoke-прогон (15–20 минут, при каждом изменении кода)

| # | Шаг | Ожидается |
|---|-----|-----------|
| 1.1 | Обновить страницу ST | Лаунчер URIS виден, в консоли нет ошибок от UR Image Studio |
| 1.2 | Клик по лаунчеру | Окно студии открывается, все вкладки (API / Генерация / Референсы / Шаблоны / Галерея / Медиа / Настройки / Мост) переключаются без ошибок |
| 1.3 | Вкладка API → «Проверить» на картинном подключении | Строка фактов заполняется, статус OK или человекочитаемая ошибка |
| 1.4 | Генерация → «Строить промпт» → запустить Шаг 1 | Промпт появляется в редакторе |
| 1.5 | «Сгенерировать» (Шаг 2) | Задача в бейдже QUEUE, результат в галерее, уведомление |
| 1.6 | Открыть картинку из галереи в просмотрщике | Лайтбокс открывается, кнопки (кроп/в референсы/копировать/удалить/звезда) на месте |
| 1.7 | Пост с `[[img: тестовый кот]]` → клик по заглушке | Инлайн-генерация стартует, картинка появляется под постом |
| 1.8 | Перезагрузить страницу | Позиция окна, вкладка, настройки чата сохранились; очередь пуста |

## 2. Окно и лаунчер

- [ ] 2.1. Перетаскивание окна за шапку; позиция сохраняется после перезагрузки.
- [ ] 2.2. Ресайз за углы: минимальные/максимальные размеры, контент не ломается.
- [ ] 2.3. Узкое окно браузера (~400 px) или эмуляция мобильного: окно уходит в полноэкранный режим, все вкладки доступны.
- [ ] 2.4. Во время генерации лаунчер пульсирует; после завершения — обычный вид.
- [ ] 2.5. Скролл таб-бара (много вкладок на узком экране): стрелки/прокрутка работают.
- [ ] 2.6. Закрытие окна во время генерации: генерация не прерывается, бейдж/пульсация видны, результат доходит.
- [ ] 2.7. Состояние свёрнутых аккордеонов на вкладках сохраняется между сессиями.

## 3. Вкладка API — подключения

- [ ] 3.1. Создание картинного подключения: все контракты выбираются из списка, форма меняет поля под контракт (openai-images / gemini-native / openrouter-images / chat-completions / pollinations-images / naistera / comfyui / cloudflare-workers-ai).
- [ ] 3.2. Неверный ключ → «Проверить»: человекочитаемая ошибка, а не голый `401`/stacktrace.
- [ ] 3.3. Неверный URL (опечатка в хосте): честная сетевая ошибка; после OPTIONS-пробы расширение не переотправляет платный запрос вслепую.
- [ ] 3.4. Клонирование подключения: копия создаётся, правки копии не трогают оригинал.
- [ ] 3.5. Удаление подключения с подтверждением; удалённое не всплывает после перезагрузки.
- [ ] 3.6. Таймаут подключения: поставить 5 с, запустить генерацию на медленной модели → задача падает по таймауту с понятным сообщением; вернуть 120 с.
- [ ] 3.7. Шаг 1: переключение «профиль Connection Manager / свой текстовый эндпоинт»; оба варианта генерируют промпт.
- [ ] 3.8. «Сбросить знания о шлюзе»: строка фактов/опыт доставки очищается.
- [ ] 3.9. Ключи: поле ключа не попадает в экспорт настроек ST; после перезагрузки страницы ключ на месте (браузер-локально).

## 4. Доставка (Авто / напрямую / прокси)

*Требует `enableCorsProxy: true`.*

- [ ] 4.1. Провайдер с CORS (OpenRouter/Gemini): «Авто» идёт напрямую, в строке фактов — direct.
- [ ] 4.2. Провайдер без CORS (Cloudflare Workers AI): первая генерация на «Авто» — тихая переотправка через прокси после OPTIONS-пробы; платный запрос ушёл один раз (проверить по дашборду/логам провайдера, если доступно).
- [ ] 4.3. Пометка «прямая не работает»: следующие генерации идут сразу через прокси; через ~30 мин или после «Сбросить знания» — возврат к прямой попытке.
- [ ] 4.4. «Только напрямую» на провайдере без CORS → честная ошибка, никаких скрытых переотправок.
- [ ] 4.5. «Через прокси» принудительно → работает; при выключенном `enableCorsProxy` — понятная ошибка.
- [ ] 4.6. Разведка перед первым POST: новое подключение, ни разу не проверенное — перед первой генерацией виден дешёвый GET (Network), затем платный POST правильной дорогой.
- [ ] 4.7. Редактирование (openai-images + референс): «Авто» перебирает диалекты multipart → JSON → img2img; рабочий диалект виден в строке фактов и запоминается.

## 5. Вкладка Генерация

- [ ] 5.1. Режим «Вручную»: свой промпт → только Шаг 2.
- [ ] 5.2. Режим «Строить промпт»: Шаг 1 → редактируемый промпт → ручной запуск Шага 2.
- [ ] 5.3. «Полный pipeline»: один клик → промпт → картинка.
- [ ] 5.4. Пустой чат / welcome-экран: понятное сообщение или генерация с настройками welcome-скоупа (проверить, что набор «Стороны/Размер/Quality/модель/шаблон» на welcome отдельный от чата).
- [ ] 5.5. Стороны × размер × quality: сетка значений; после генерации фактические пиксели картинки совпадают с запрошенными; если шлюз схалтурил — warning `aspect-mismatch`.
- [ ] 5.6. Смена модели в селекте; несуществующая модель → человекочитаемая ошибка.
- [ ] 5.7. Пресеты параметров: сохранить пресет, применить, переименовать, удалить.
- [ ] 5.8. «Вставить шаблон»: инструкция выбранного шаблона попадает в редактор, макросы {{char}}/{{user}} подставлены; сам шаблон не изменился.
- [ ] 5.9. Настройки генерации — per-chat: в чате А поставить 16:9, в чате B 1:1 → переключение чатов меняет значения корректно.

## 6. Очередь и бейдж QUEUE

- [ ] 6.1. «Сгенерировать» три раза подряд с разными промптами: три задачи в ленте, каждая ушла со своим снапшотом промпта (проверить по метаданным результатов).
- [ ] 6.2. Бейдж: цифра = живые задачи; при 0 — приглушён, но лента открывается.
- [ ] 6.3. Отмена ожидающей задачи крестиком; выполняющаяся не снимается крестиком.
- [ ] 6.4. «Остановить очередь»: гасит текущую и ожидающие. При прямой доставке — честная отмена (fetch abort в Network); при прокси — только ожидание (предупреждение в UI/доке).
- [ ] 6.5. Упавшая задача → «Повторить» (тот же снапшот промпта).
- [ ] 6.6. Смена чата с ожидающими задачами: они отменяются с одним уведомлением; выполняющаяся не прерывается.
- [ ] 6.7. Защита от устаревшего состояния: отправить задачу по посту → отредактировать пост до старта задачи → задача отменяется с ошибкой.
- [ ] 6.8. Перезагрузка страницы с ожидающими задачами: очередь пуста (задачи потеряны — документировано), промпты сохранились.
- [ ] 6.9. Таймаут зависшего запроса (искусственно, через DevTools → Network throttling/блокировку): задача падает по таймауту подключения.
- [ ] 6.10. Настройка «Авто-повтор при неоднозначной доставке»: выкл (дефолт) — нет повторов; вкл — одна автопереотправка через прокси.

## 7. Инлайн-картинки в чате

- [ ] 7.1. Пост с `[[img: …]]` — заглушка отрисована на месте маркера, маркер не виден как сырой текст.
- [ ] 7.2. Ручной режим: генерация только по клику на заглушку.
- [ ] 7.3. Автоматический режим: генерация стартует сама; ограничение очереди соблюдается (заспамить 5+ маркеров — лишние ждут/отклоняются по лимиту).
- [ ] 7.4. Свой тип маркера: создать триггер-профиль «Селфи» с алиасами `[[селфи: …]]`, своим соотношением сторон и политикой референсов → маркер срабатывает, параметры профиля применяются.
- [ ] 7.5. Кнопка-камера в меню поста: генерация по посту без маркеров.
- [ ] 7.6. Маркер в посте модели (streaming): после завершения стрима заглушка появляется корректно, без гонок.
- [ ] 7.7. Редактирование/удаление поста с инлайн-картинкой: поведение заглушки и сгенерированной картинки корректное.
- [ ] 7.8. Клик по инлайн-картинке → просмотрщик (лайтбокс) с полным набором действий.
- [ ] 7.9. Компакт-режим чипов инлайн-превью (если включён) — переключение, отображение.

## 8. Референсы

- [ ] 8.1. Загрузка одиночная и пачкой (5+ файлов сразу).
- [ ] 8.2. Кроп при загрузке и из редактора карточки; кроп вертикальной и очень широкой картинки.
- [ ] 8.3. Клонирование референса: копия поверх той же картинки; правки расходятся независимо.
- [ ] 8.4. Папки референсов: создать, переместить, удалить.
- [ ] 8.5. Привязка папки к чату → генерация автоматически прикладывает подходящие референсы (проверить в Network, что картинки ушли в запросе).
- [ ] 8.6. Режимы отправки «авто / всегда / никогда» в настройках подключения — три прогона.
- [ ] 8.7. Лимиты референсов провайдера: превышение (например, Cloudflare SDXL — 1 референс) → понятное сообщение/обрезка, не молчаливый сбой.
- [ ] 8.8. Библиотека референсов (refs-library): сохранение/переиспользование между чатами.
- [ ] 8.9. Удаление референса, привязанного к активной генерации/чату.

## 10. Галерея

- [ ] 10.1. Новые генерации появляются в галерее (нативная галерея ST + серверный индекс).
- [ ] 10.2. Избранное: звезда на карточке и в просмотрщике; избранное закреплено наверху, золотая звезда на миниатюре, подсветка карточки; снятие звезды.
- [ ] 10.3. Режимы «Все / Папки»: переключатель в тулбаре; чипы «Все / Без папки / папки» со счётчиками; счётчики сходятся с фактическим числом картинок.
- [ ] 10.4. Создание папки «＋» из галереи; назначение картинки в папку через меню карточки и просмотрщика («Папки…», мульти-выбор); одна картинка в нескольких папках.
- [ ] 10.5. Сортировка чипов («⋯»): свой порядок / по имени / по количеству; drag-порядок сохраняется.
- [ ] 10.6. ПКМ/долгий тап по чипу папки: переименовать, цвет, удалить; удаление папки не трогает картинки.
- [ ] 10.7. Выбранный режим и папка — настройка устройства: в другом браузере/профиле значения независимы.
- [ ] 10.8. Просмотрщик: копирование в буфер, удаление (с подтверждением, картинка исчезает из галереи и индекса), кроп, «сделать референс», отправка в референсы.
- [ ] 10.9. Пустая галерея / галерея после удаления всех картинок — заглушки без ошибок.
- [ ] 10.10. Большая галерея (100+ картинок): скролл, ленивая подгрузка, производительность.

## 12. Настройки, данные, диагностика

- [ ] 12.1. Уведомления: включить звуки → сигнал при завершении этапов (Web Audio); выключить — тишина.

## 13. Устойчивость и граничные случаи

- [ ] 13.1. Обрыв сети посреди генерации (DevTools offline): честная ошибка, задачу можно повторить.
- [ ] 13.2. ST перезапущен во время генерации через прокси: после возврата — осмысленное состояние задачи.
- [ ] 13.3. Два окна/вкладки ST одновременно (cross-tab): генерации и галерея не конфликтуют, дубли не плодятся.
- [ ] 13.4. Очень длинный промпт (10k+ символов): UI не ломается, ошибки провайдера отображаются.
- [ ] 13.5. Спецсимволы/эмодзи/CJK в промпте, имени папки, описании референса.
- [ ] 13.6. Отключить расширение в Manage Extensions → включить: чистое выключение без ошибок в консоли, состояние сохранено.
- [ ] 13.7. Открыть чат с картинками, сгенерированными «старой» версией расширения (если есть история): обратная совместимость индекса/метаданных.
- [ ] 13.8. Консоль и Network после полного прогона: нет необработанных исключений, нет утечки повторяющихся запросов (поллинги останавливаются).

## Форма отчёта

По каждому кейсу: ✅ / ❌ / ⏭ (пропущен, причина). Для ❌ — шаги воспроизведения, текст ошибки из консоли/тоста, скриншот, ссылка на диагностический дамп. Сводка в конце: блок → всего/прошло/упало.

## Приоритеты при нехватке времени

1. Smoke-прогон (раздел 1) — всегда.
2. Очередь и отмена (раздел 6) — самая рискованная логика.
3. Доставка/прокси (раздел 4) — деньги пользователя, двойные платные запросы недопустимы.
4. Инлайн (раздел 7) — основной сценарий «в чате».
5. Галерея: избранное и папки (раздел 10) — свежий код последних коммитов.
