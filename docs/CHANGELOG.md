## 2026-09-10 — v0.8.6 (experimental): внешний мост `globalThis.URIS` — headless-генерация для других расширений

## 2026-09-08 — v0.8.6: оптимизация референсов v3 — webp исключён из провайдер-пути

- **Причина**: релей-апстримы за OpenAI-совместимыми шлюзами (adobe2banana, инцидент 2026-09-08) отклоняют webp на контент-валидаторе («Image edit file content does not match its declared MIME type», HTTP 400), хотя браузер кодирует корректно; исходный webp-файл мог уйти на провод через source pass-through.
- **Решение**: `OPTIMIZATION_VERSION = 'ref-v3-1024'`; канонические форматы — jpeg (opaque) / png (alpha); webp убран и из `CANONICAL_MIMES`, так что source pass-through больше не пропустит webp-оригинал. `options.formats` позволяет вызову явно закрепить набор: миниатюры галереи пинят webp (`native-image-storage.js`) — они локальные (URIS_Thumbs не сканируется в галерею) и до провайдеров не доходят. Инструментация `[refs] optimize: …` пишет в лог, какой формат реально ушёл на провод и почему (до подтверждения фикса инцидента).
- **Тесты**: `tests/references.test.js` — v3-каскад (jpeg/png по альфе, formats-пин, source pass-through без webp).

Итог глубокого code review с перепроверкой по исходникам ST (полная таблица находок и два deep-dive документа: `docs/deep-dive-stage2-dispatch.md`, `docs/deep-dive-generate-tab-render.md`). Все правки внесены по плану P1→P2; полный набор тестов зелёный.

- **P1 — кросс-постовая запись промпта** (`src/ui/tab-generate.js`): debounced autosave читал `state.currentMsgId` в момент срабатывания, а замкнутый `promptEl` после перерендера — detached-узел со старым текстом. Тесты: «Stop-all cancels a queued (chained) Stage 2 before it starts; it never reaches the provider», «stage2 chain is keyed per chat: the same msgId in another chat does not wait».
- **P2 — устаревший рендер побеждал свежий** (`src/ui/tab-generate.js`): прямые вызовы `render(root)` (навигация по постам, include/exclude референсов, смена модели) не инкрементировали `__urisRenderEpoch` — два параллельных рендера делили один epoch, и завершившийся позже устаревший перезаписывал DOM (редактор показывал один пост при `currentMsgId` другого, под платной кнопкой). Фикс: `render()` сам инкрементирует epoch первой строкой; восстановление скролла в `tabs.js` использует свой счётчик и не задето.
- **P2 — молча пустая вкладка «Генерация»** (`src/ui/tab-generate.js`): `resolveModelChoices()` → `resolveChatConfigSnapshot()` → `assertImageModelEligible()` бросает, если свежий каталог переклассифицировал сохранённую модель чата как non-image; reject рендера глотался в `tabs.js` — вкладка оставалась пустой без единого сообщения. Фикс: catch с деградацией к селекту «нет коннекта» + `recordUrisError`/toast с причиной; тот же throw из fire-and-forget `updatePostInfo → refreshReferencePanel` (unhandled rejection + полупустая панель референсов) закрыт обёрткой `safeReferencePolicy()` в `renderLivePreview`/`renderCap`.

## 2026-09-08 — v0.8.6: API-ключ больше не стирается автоматически при правке коннекта

- **Симптом**: после неудачного запроса генерации ключ пропадал из коннекта — поле «Ключ» в карточке пустое, следующая генерация падала с `MISSING_API_KEY`.
- **Причина**: fingerprint-guard в `connection-store.js` — `updateConnection` сравнивал отпечаток `{endpoint, provider(=apiFamily)}` до/после и при расхождении молча вызывал `clearConnectionApiKey`. `apiFamily` — производное нормализатором поле (route contract / пин диалекта), поэтому клик «Попробовать …» в панели референсов — штатное восстановление после отклонения референсов (tab-generate.js) — или смена «Протокол» в карточке меняли отпечаток и стирали ключ. Смена endpoint стирала by design (запись 2026-09-05).
- **Решение** (сознательное: ключ не должен исчезать вообще): guard снят целиком, включая запись fingerprint-meta. Ключ привязан к id коннекта, а не к endpoint/протоколу; сценарий «ключ не должен уехать на чужой шлюз» для копий уже решён дизайном клонирования (ключ не копируется, вводится заново). Ключ покидает хранилище только явными действиями: удаление коннекта или сохранение пустого поля «Ключ». Протухший ключ на переправленном endpoint даст видимую 401 — восстановимо, в отличие от молчаливой потери.
- **Legacy**: `uris_api_key:<id>:meta` записи старых сборок больше не пишутся/не читаются; подчищаются при следующей записи/очистке ключа и при удалении коннекта.
- **Тесты**: `tests/connection-store.test.js` — «updateConnection never erases the browser-local key» (смена диалекта / evidence write-back / смена endpoint), «the key leaves storage only through explicit actions» (пустое поле, deleteConnection), проверка очистки legacy-meta. Полный набор зелёный (1036).
