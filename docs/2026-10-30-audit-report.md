## 2. Вердикт по семи осям ТЗ

1. **Архитектура** — сильно. Точка входа 412 строк, ленивые импорты табов, слои выражены, реестр провайдерских контрактов с версиями. Ревью подтвердило дисциплину: снапшоты конфига до первого `await`, контроллеры в `activeGenerations` до любого ожидания, late-ответы гейтятся.
2. **Надёжность** — ядро хорошо (отмена до транспорта, coalescing, retry-снапшоты), хранилища слабее: P1 unload-флаш шардов, P2 corrupt-ремонт.
3. **Данные** — слоисто (user-files + шардирование + chatMetadata + localforage), но два реальных риска потери данных (P1-2, P2-1) и документированное воскресение записей (P2-3).
4. **API-слой** — лучшая часть: preflight-oracle, no-resend при ambiguous, сериализация на подключение. Одна дыра: 5xx считается «доказательством диалекта» (P1-5).
5. **Безопасность** — DOM-XSS чисто (все 88 HTML-стоков экранированы или на DOM-API; импорты через SAFE_ID_RE), но два P1 по утечке ключей в выгрузках диагностики/дампа.
6. **Тесты** — 1770 детерминированных, включая тесты безопасности и CSS-контрактов; 1 осознанный skip; нет CI.
7. **Документация** — README/USER_GUIDE сильные; рассинхрон «secret storage» исправлен коммитом `d28e522`; CHANGELOG-файла нет (у BB-CF есть).

**Сравнение с BB-CF:** по коду URIS строже по всем осям, кроме размера аудитории документации (полный EN-гайд, CHANGELOG) — заимствовать там почти нечего, см. §7.

## 4. P1

### P1-1. Две вкладки: автоматизация запускает полный платный пайплайн в обеих *(частично покрыто roadmap п.2)*
- **Файл:** `src/cross-tab.js:22-35` ('busy' только баннер), `index.js:196-229` (биндинг безусловен), `src/pipeline-stage1.js:262-295` (гонка `autoDoneFp`: пишется после Stage 2, читается на старте), `src/inline/scanner.js:86-97` (ключевое слово в MESSAGE_SENT ставит задачу в обеих вкладках).
- **Сценарий:** один чат в двух вкладках → оба события рендера стартуют Stage 1 (платный) + Stage 2 (платный) ×2; `_autoRunning` перштабный.
- **Фикс:** вкладке с `lockState === 'busy'` не биндить `onAutomation` и inline-scanner (это и есть roadmap п.2) **плюс** дополнительно: перечитывать `autoDoneFp` между Stage 1 и Stage 2.
- **Тест:** в roadmap §8 («вторая вкладка не слушает события генерации»).

### P1-2. Шардированный стор: unload-флаш может отправить манифест, называющий недоставленный шард → перманентный readonly / потеря записи *(проверено чтением кода)*
- **Файл:** `src/sharded-file-store.js:1099-1142` (флаш), `:345-374` (кирпич `readonly`), `:758-782` (выбрасывание чужой строки вторым писателем).
- **Сценарий A:** `flushOnUnload` (на каждом `visibilitychange → hidden`, `index.js:276-290`) шлёт шард и манифест параллельными keepalive-`fetch` без ожидания; async-отказ шарда никем не наблюдается, гейт считает только over-limit → Wi-Fi-блик: шарда нет, манифест есть → следующая сессия `shard-unreadable` → `readonly` до ручного удаления манифеста; комментарий модуля сам признаёт «nothing recovers a manifest naming a missing shard».
- **Сценарий B (два писателя):** вкладка B при merge видит чужую строку с недоставшимся шардом → `adoptForeignShard` 404 → строка выбрасывается из манифеста → шард-сирота, которую никто не прочитает.
- **Фикс:** (1) при `'missing'` с `row.count > 0` — recovery-путь `rebuildFromScan()` вместо кирпича; (2) в `flushOnUnload` считать сетевые отказы шарда (`.catch` + счётчик `failed`, симметрично `skipped`) и подавлять манифест.
- **Тест:** мок-сеть: shard-fetch отклонён при unload → манифест не уходит; 404 шарда при загрузке → скан, не readonly.

### P1-3. Ключ, встроенный в URL эндпоинта, утекает в diagnostic-dump через лог-буфер *(проверено чтением кода)*
- **Файл:** `src/providers/gemini.js:66` и `src/providers/openai.js:61` (`error('… сетевая ошибка', url, …)`), `src/core.js:364` (`push` без редакции), `:381-384` (`dumpProblemLog`), `src/diagnostic-dump.js:45,85-91`.
- **Сценарий:** эндпоинт `https://…/v1beta?key=AIza…` (нормализация query не вырезает) → любой сетевой сбой пишет полный URL в console и `logBuffer` → «Диагностика» (файл для пересылки) уносит ключ открытым текстом. `error-pool.safeErrorText` на этом пути не вызывается.
- **Фикс:** редакция на границе буфера — прогонять аргументы `log/warn/error` через `safeErrorText`-нормализацию перед `push()` (или минимум перед `dumpProblemLog`/`dumpDebugLog`).
- **Тест:** `error('x', 'https://host/v1?key=SECRET')` → `dumpProblemLog()` не содержит `SECRET`.

### P1-4. netdump `scrubUrl` сохраняет userinfo — basic-auth-креды эндпоинта в выгружаемом дампе *(проверено чтением кода)*
- **Файл:** `src/netdump.js:258-267`, экспорт `:459-494`.
- **Сценарий:** эндпоинт `https://user:pass@gateway/…` → scrubUrl редактирует только query-параметры → `user:pass@` остаётся в authority → `uris-network-dump-*.json` («evidence-файл») уносит креды; нарушение собственного контракта модуля (netdump.js:16-23).
- **Фикс:** в `scrubUrl` — `url.username = ''; url.password = '';` + расширить список query-параметров (`password|secret|auth|sig`).
- **Тест:** scrubUrl('https://u:p@h/x?key=k') → без `u:p@` и без `k`.

### P1-5. openai-images: 5xx JSON-ноги считается «доказательством диалекта» → img2img-нога уходит вторым платным POST *(проверено чтением кода)*
- **Файл:** `src/providers/image-openai.js:290-294` (`isDialectCandidate` отбрасывает только 401/402/403/429), переход на img2img `:419-427,465-472`.
- **Сценарий:** multipart заблокирован CORS → легитимный переход на JSON-ногу → шлюз отвечает 502/504 (апстрим мог принять и списать) → статус не в стоп-листе → сразу `runImg2imgLeg` → вторая оплата; противоречит глобальному принципу «ambiguous → no resend».
- **Фикс:** исключить 500/502/503/504 из `isDialectCandidate` (это исход ноги, а не отвергнутый диалект) либо гейтить переход бесплатной пробой, как сделано для 400 (`proxiedAuthBroken`).
- **Тест:** JSON-нога с 502 → ошибка терминальна, img2img не вызывается.

## 5. P2

1. **file-store «ремонтирует» corrupt-документ пустым зеркалом сразу и безвозвратно** — транзиентная обрезка ответа (флаки-сеть/туннель — штатный сценарий расширения) стирает шаблоны/пресеты/папки без бэкапа. `src/file-store.js:439-453,504-509`. Фикс: re-read ×2, перед ремонтом — side-файл `<name>.corrupt`. Тест: обрезанный 200 → данные не потеряны.
2. **Авто-пайплайн: cold `import()` создаёт окно, где конфиг снимается после смены чата** — первая после загрузки авто-генерация платит за чат A с конфигом чата B. `index.js:199-212`, `src/pipeline-stage1.js:127,260-262`. Фикс: захватывать `chatConfig` синхронно в `onAutomation`.
3. **Воскрешение записей при merge по updatedAt** (две вкладки) — осознанное ограничение, задокументировано в коде и в `it.skip`-тесте (`tests/file-store-merge.test.js:203-239`); наивный фикс хуже, проверено живьём 2026-10-03. Стратегия: tombstones или If-Match; сейчас — принятый риск.
4. **extraBody может унести ключи в бэкап** вопреки диалогу «API-ключи не переносятся»: `isSecretKey('key'|'secretkey')` = false. `src/image-connection-schema.js:41-48,397-401`, `src/data-port.js:166-176`. Фикс: расширить `SECRET_KEYS` + суффиксное правило.
5. **`imagePath` импортированного референса не канонизируется** — произвольный внешний URL в `<img src>` каждой плитки и в `fetch()` при генерации (пинг атакующему с подтверждением импорта). `src/refs-library.js:239-249` (карточки галереи на том же пути канонизируются — `gallery-index.js:151`). Фикс: `canonicalizeNativeImagePath` в `normalizePoolReference`.
6. **autoRetryAmbiguous — осознанный автоматический повтор неоднозначной доставки** (второе списание при неудаче). Opt-in, default false, строго один раз. `src/pipeline-queue.js:203-232`. Фикс желателен: проверять `findQueuedDuplicate` перед авто-повтором; текст настройки — «первая попытка могла быть оплачена».
7. **Мост: `buildPrompt` мимо автолейна** — внешнее расширение в `Promise.all` даёт N параллельных платных text-LLM вызовов. `src/bridge.js:765-873` (контраст: `generate` — `:618-636`). Фикс: обернуть в `enqueueAutoLane`.
8. **Мост: включённый тумблер = постоянное согласие** — после включения любое sibling-расширение вызывает `URIS.generate()` безлимитно, per-caller confirm/allowlist нет (сам модуль признаёт: «permission UI is NOT implemented yet», `bridge.js:22-24`). Фикс: allowlist с UI-согласием при первом вызове нового caller + мягкий бюджет.
9. **Ручная генерация слепа к активной авто/мостовой генерации того же поста** — `findQueuedDuplicate` видит только очередь; авто-полёт живёт в `activeGenerations`. `src/pipeline-queue.js:278-283`, `src/pipeline-stage2.js:145-151`. Фикс: сверять промпт с `activeGenerations` + confirm.
10. **Две вкладки, ручные пути: дедуп и семафор провайдера перштабные** — два явных клика в двух вкладках = два параллельных платных POST. `src/image-api.js:246-249`. Закрывается фиксом P1-1 или Web Locks вокруг `serialize('uris-provider:…')`.

## 7. Заимствования из BB-Comic-Forge

Кода брать нечего — диалектная машина URIS строже фолбэков BB-CF (у них переход images-edit → text-only по регэкспам текста ошибки; у URIS — preflight-oracle и структурные коды). Полезны три организационные практики:

1. **CHANGELOG.md** — у BB-CF 23KB двуязычной истории с датами; у URIS файла нет вовсе (версия видна только из git). Дёшево завести, см. roadmap п.24.
2. **Раздел «Ограничения» в README** (roadmap п.8 уже запланирован) — дополнить найденными аудита границами: merge-воскресение (P2-3), `readonly`-кирпич шардов до фикса P1-2, «первая попытка могла быть оплачена» для autoRetryAmbiguous.
3. **Полный EN-гайд** (roadmap п.10) — у BB-CF README.en.md полный; у URIS EN только в шапке.

Обратное сравнение: у BB-CF взять нечего в ответ — innerHTML-доверие сохранённому HTML, plaintext-ключ в console API, 7 тестов. Подтверждает вердикт экспресс-фазы.
