# Мобильный UX-проход: референсы и галерея — дизайн

- Дата: 2026-10-03
- Статус: согласован с пользователем (подход B «мобильные паттерны поверх», жестовая модель карточных действий)
- Затронутое: `src/ui/tab-references.js` (мобильный путь <480px), `src/ui/tab-gallery.js`, `src/ui/gallery-actions.js` (новый компонент меню), `style.css`, тесты
- Масштаб пользователя: ~40 папок, ~200 референсов; обе ориентации телефона

## Проблема

На телефоне болят две вкладки:
- **Референсы**: строки папок визуально слепы (3 миниатюры 28×36), до другой папки только через «Назад», кнопки редактора не в зоне большого пальца.
- **Галерея**: 5 кнопок под каждой плиткой переносятся строками и захламляют сетку; тулбар тесный.

Лайтбокс, INFO/QUEUE, вкладка «Генерация» — не трогаем (пользователь устроен).

## Что уже есть (опора, не ломаем)

- Референсы <480px: трёхэкранный путь `_renderMobileAll` — «Папки» (поиск, пины, превью-точки) → «Сетка» (поиск, счётчик) → «Карточка» (полный редактор). Навигация back-стеком, `uris-mobile-*` классы.
- Галерея: CSS-отзывчивость, карточные кнопки уже 44px на мобильном; тап по картинке = лайтбокс (PhotoSwipe).
- Оверлей-меню: `uris-picker-overlay.uris-crop-overlay` (`z-index: --uris-z-modal-top`, поднимается даже над лайтбоксом) — паттерн существующего меню копирования.
- `contextmenu` уже нигде не перехватывается; `touch-action`-контракты в CSS.

## Дизайн

### 1. Общий жест: карточное меню (новый компонент)

**Одно событие — все указатели.** `contextmenu` покрывает ПКМ (десктоп) и долгий тап (Android Chrome). Для iOS Safari — таймер долгого тапа: `pointerdown` → 500 мс → открыть, отмена при `pointermove` > порога / `pointerup` / `pointercancel` / скролле.

- Мобильный (<768px): снизу, action-шит (заголовок-грип, элементы-кнопки 44px, фоновый тап закрывает).
- Десктоп: поповер у курсора (тот же элемент, другое позиционирование в `@media`).
- Элементы — обычные кнопки; «Удалить…» всегда с существующим подтверждением.
- Реализация: `openCardActionMenu({ title, items, x, y })` в новом `src/ui/card-action-menu.js`, хост — тот же оверлей-паттерн `uris-picker-overlay`; один открытый экземпляр, повторный вызов закрывает предыдущий; снятие при re-render вкладки.
- `event.preventDefault()` на перехваченном `contextmenu` (гасит нативное меню браузера).

### 2. Референсы

**а) Список папок — коллаж 2×2 (твоя идея, в списке, а не лентой).**
В мобильном экране «Папки» точки-превью (3 × `uris-mobile-folder-thumb` 28×36) заменяются коллажем 2×2 из первых четырёх референсов папки (те же `imagePath`, `background-size: cover`, `loading` не нужен — background-image; ленивость даёт сам факт малых размеров). Строка ~56px: [📌] [коллаж 36×32] [имя + счётчик] [›]. Меньше 4х — пустые ячейки, 0 — плейсхолдер. Поиск, пины, «+ Папка», «+ Референс», «⚙» — как есть.

**б) Экран «Сетка» — переключение папки без «Назад».**
Чип с именем папки в тулбаре (`uris-mobile-toolbar-title`) становится кнопкой: открывает нижний лист со списком папок — поиск сверху, «Все»/«Без папки» первыми, закреплённые с 📌, счётчики; сетка остаётся видна сверху (лист занимает нижние ~55%). Выбор — фильтр сетки, лист закрывается. Список переиспользует рендер строки папок из (а) — один рендерер на оба места. Управление папками (пин/цвет/переименование/удаление) остаётся на экране «Папки» (через «‹») — в листе только переключение, чтобы не дублировать редактор папок.

**в) Экран «Карточка» — липкий низ.**
`uris-ed-footer` (Клонировать/Удалить) на мобильном экране карточки прижимается к низу (`position: sticky; bottom: 0` внутри скролла + фон/градиент), кнопки 44px. Поля — одна колонка, шапка с именем и «Автосохранение» остаётся сверху.

### 3. Галерея

**а) Мобильный (<768px): плитки без кнопочных строк.**
`@media` прячет `.uris-card-actions`; вся плитка — картинка. Тап = лайтбокс (не меняется). Долгий тап / ПКМ = карточное меню (п. 1) с элементами: Регенерировать, Копировать промпт, К посту-источнику (если `sourceMsgId`), Сохранить как референс, Удалить… Пустых зон-посредников нет — никакого «режима выбора».

**б) Десктоп (≥768px): всё как было + ПКМ.**
Кнопки под карточками остаются; ПКМ по плитке открывает то же меню поповером у курсора — быстрый путь, ничего не убираем.

**в) Тулбар — липкая компактная строка.**
`uris-gallery-toolbar` на мобильном: `position: sticky; top: 0` внутри контейнера вкладки, счётчик слева, «Обновить»/«Очистить» — иконки 44px справа, подписи убраны (`aria-label` остаются). «Очистить» — с существующим подтверждением.

### 4. Жест в референсах (симметрия)

Долгий тап / ПКМ по свёрнутой карточке референса в сетке: Правка (открывает экран карточки), Клонировать, Вкл/Выкл, Удалить… Тап — как сейчас (разворот/экран карточки). На десктопе ПКМ — добавка к существующему поведению.

## Не-цели

- Лайтбокс, INFO/QUEUE, «Генерация», «Шаблоны», «API» — без изменений.
- Десктопные раскладки не меняются (ПКМ и жестовое меню — добавка; CSS-правила только внутри `@media (max-width: 768px)` / `(pointer: coarse)`).
- Референсовский мобильный путь остаётся <480px (`REFS_MOBILE_BREAK`): ландшафтный телефон получает десктопную двухпанельную раскладку (пользователю ок — «важнее плотность»), жестовое меню работает на любой ширине.
- Нового хранилища нет; коллаж читает те же `imagePath`.

## Краевые случаи

- iOS: долгий тап не шлёт `contextmenu` — только таймер; отмена при движении пальца (скролл сетки не должен открывать меню).
- Быстрый скролл с касанием плитки: `pointermove` сверх порога гасит таймер до срабатывания.
- Re-render вкладки/чата при открытом меню — меню снимается (хост-оверлей удаляется вместе с содержимым; подписчики `visibilitychange`/unload не текут).
- Двойной жест (второй долгий тап при открытом меню) — предыдущее меню закрывается, новое открывается.
- Кнопка «К посту-источнику» скрывается, если `sourceMsgId == null` (как сейчас `gotoBtn`).
- Sticky-тулбар и sticky-футер не должны ломать существующие `touch-action: pan-y` контракты (проверить на ручных репро-страницах).

## Тестирование

- **CSS-контракты** (паттерн `template-css.test.js`): правила «спрятанные действия карточки», «sticky тулбар», «sticky футер редактора», «коллаж 2×2», «лист ≥55% с видимым гридом» — существуют внутри нужных `@media`.
- **Fake-dom**: `openCardActionMenu` открывается по `contextmenu` (элементы, порядок), закрывается по фоновому тапу/Esc; iOS-таймер — срабатывание через 500мс, отмена при `pointermove`; галерея: элемент «Регенерировать» вызывает тот же обработчик, что старая кнопка; лист переключения папки: фильтр, выбор, обновление чипа; коллаж: первые 4 референса, пустая папка — плейсхолдер.
- **Регресс-щит**: существующие наборы `tab-gallery*`, `tab-references*`, `gallery-crop-actions`, `lightbox-closing-hit-test` проходят без ослабления; десктопное поведение не меняется.
- **Ручное**: обновить `tests/manual/refs-mobile-scroll.html` / `popup-mobile-repro.html` или добавить `gesture-menu.html` — проверить на реальном телефоне: жест в обеих ориентациях, липкость тулбара, клавиатура в редакторе.
