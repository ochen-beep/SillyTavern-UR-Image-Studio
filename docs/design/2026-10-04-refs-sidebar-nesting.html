Сайдбар папок — варианты перестройки (to-be, окт 2026)

Продолжение карты макета. Опирается на UX-исследование: иерархия выгодна мелкой (2 уровня), папки — для стабильной структуры, мульти-присвоение (уже есть в URIS) — для пересекающихся признаков. Твоя интуиция «сложить папки в папки» подтверждается практикой референс-менеджеров — с одной важной оговоркой о глубине.

Вариант A — вложенные папки: группа → папки рекомендую

Глубина ровно 2: «Лица» содержит «Лицо Рады», «Мимика», … Вложенность папок в папки глубже — нет. Тап по группе = все референсы группы (счётчик рекурсивный). Тап по подпапке = как сейчас. Мульти-присвоение folders[] сохраняется без изменений — вложенность это навигация, а не смена модели владения.

Альтернативы — и почему они хуже для твоей задачи

B · Группы-заголовки без контейнеров дёшево

Папки остаются плоскими, но список размечается секциями («Лица», «Сцены») — как разделители в букмарк-баре.

+ минимум кода, нулевой риск для данных
− группа не открывается: нельзя сказать «покажи всё из Лиц»
− второй концепт рядом с папками = путаница («референс в группе или в папке?»)
− при 40+ папках секции помогают слабо — список всё равно длинный

Честно: это костыль. Стоит брать, только если вложенность окажется слишком дорогой в реализации.

C · Плоский список + авто-группировка дёшево

Ничего не меняем в данных: сортировка по алфавиту с буквенными разделителями, группировка по цвету, компактная плотность, быстрый прыжок по буквам.

+ вообще без миграции
− буквенные разделители бесполезны, когда имена смысловые («Лицо Рады», «Сцены»)
− clutter остаётся: 40 строк всё так же на экране

Честно: это не решение задачи «куча папок засоряет», а косметика. Годится как дополнение к A, не вместо.

Мобильный при варианте A — drill-down вместо inline-раскрытия

На телефоне группы не сворачиваются, а открываются как отдельный экран стека (как iOS Files): тап по группе → список её папок. Стек становится 4-экранным: группы → группа → сетка → карточка. Коллаж группы собирается из референсов всего поддерева.

Честные предупреждения — где можно налажать

Не давать глубину 3+. Как только «Сцены → Город → Ночь» станет можно, кто-нибудь это сделает — и поиск/счётчики/мобильный стек усложнятся ради случая, который не нужен. Жёсткий кап в коде, не «просто не рисуем кнопку».
Не ломать существующие папки. parentId — необязательное поле; все старые хранилища, экспорт-импорт и тесты должны работать без изменений. Никакой миграции данных.
Не прятать пины. «Избранное» уже решает часть проблемы clutter'а — группы должны жить рядом с ним, а не вместо. Пиновать можно и группу, и папку.
Пять мест правки одной модели. Сайдбар, мобильный стек, folder-picker (чипы + шит), менеджер папок (слияние), белый список генерации. Если менять только сайдбар — получим расхождение понятий между экранами. Изменение одно — parentId + рекурсивный хелпер, но трогать надо все пять потребителей.
