## 1. Правила исполнения (гигиена + ponytail)

Приоритет при конфликте: `BEEP_DEV_HYGIENE.md` задаёт оформление и лимиты,
ponytail задаёт минимальность решения. Никогда не упрощать (обе инструкции
сходятся): валидацию на границах доверия, обработку ошибок против потери
данных, безопасность, подтверждения на деструктивных действиях.

1. **Коммиты:** EN, одна строка ≤72 символов, conventional (`fix(queue): …`).
   Один шов = один коммит. Косметических соло-коммитов нет.
2. **Комментарии в коде:** EN, только рядом с изменённой логикой. Запрещены
   ссылки на номера пунктов плана/аудита (`P0-1`, `п.14`), file:line ядра ST,
   внутренние шифры. Только инженерная причина неочевидного ограничения.
3. **Лестница ponytail перед каждой задачей:** нужно ли вообще → переиспользовать
   существующее в кодовой базе → stdlib/платформа → одна строка → минимум кода.
   Перед правкой grep всех вызывающих функции — фикс в общем шве, а не в каждом
   вызывающем. Осознанные упрощения — `ponytail:`-комментарий с потолком и путём
   апгрейда.
4. **Лимиты файлов:** JS ~700 строк. Сейчас нарушают 9 файлов
   (см. §6). Правило: **трогаешь нарушитель по существу — предложи сплит**;
   реализация сплита — отдельный refactor-коммит перед фичей, максимум один
   сплит за этап; остальное — в backlog размеров с конкретным предложением.
   style.css 283 строк — ок, CSS не трогаем.
5. **Тесты:** нетривиальная логика уходит с минимум одним раннабл-чеком;
   пути денег/секретов — полный `npm test` ×3 (должен быть идентичным).

## 2. Окружение ручных тестов

- Бокс: `http://127.0.0.1:8001/` (staging, данные `data/default-user/`).
- Правки расширения подхватываются жёстким обновлением страницы (Ctrl+F5);
  правки manifest.json — тоже.
- QA-бокс содержит живые данные (пул 291+ карточек). **Перед деструктивными
  ручными сценариями** (свип, чистки) — экспорт бэкапа через Настройки →
  Экспорт и копия `user/images/URIS_*` + `user/files/URIS*`.
- Быстрый прогон одного файла: `node --test tests/<name>.test.js`.

## 3. Цикл исцеления от багов (применяется в каждом ручном прогоне)

1. Зафиксировать: шаги воспроизведения, скрин/консоль, ожидание vs факт.
2. Воспроизвести детерминированно (в идеале — моком в node-тесте).
3. Найти корневой шов: общая функция, через которую идут все вызывающие.
4. Написать падающий автотест на этот шов.
5. Минимальный фикс (лестница).
6. `npm test` зелёный (деньги/секреты — ×3).
7. Перепроверить руками на 8001 тем же клик-путём.
8. Коммит по шву.

Ручной баг без нового автотеста считается незакрытым.
