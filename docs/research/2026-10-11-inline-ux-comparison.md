## 1. Как инлайн работает в URIS (сводка)

Маркер `[[тип: описание]]` (алиасы триггер-профилей) в тексте поста → чистая грамматика
(`src/inline/grammar.js`, code-fence aware, ReDoS-safe) → сканер ставит задачи только в
auto-режиме и только для первых `cap=3` маркеров (`src/inline/runner.js:82`) → платные
вызовы сериализует автолейн (общая полоса с bridge) → DOM-слой (`src/inline/render.js`)
реконсиляцией держит в `.mes_text` оболочки по статусам: готовая картинка (клик → общий
лайтбокс по всем готовым картинкам поста), pending-заглушка со спиннером и ✕, кликабельные
строки «📷 Нарисовать» / «Описание изменилось» / «Ошибка: … — клик: retry». Ручная
📷-кнопка в меню поста шлёт первые 4000 символов текста поста как описание
(`render.js:610-639`); `tab-media.js:41` ставит только `reroll`, т.е. отдельного
onManual-пути нет. Состояние слота — в `chatMetadata.uris_inline` (`src/inline/store.js`),
**текст чата не мутируется никогда**. Лайтбокс — PhotoSwipe с тулбаром
копировать/кроп/в-референсы/перегенерировать/удалить (`src/ui/lightbox.js:194-205`).

Ключевые контракты, важные для рекомендаций ниже:

- Готовый (оплаченный) item не откатывается в pending/error: гарды в `store.js:78` и
  `runner.js:257-263`. Реролл готовой картинки **не меняет её вид в чате** — старое
  изображение остаётся до приезда нового, без какого-либо индикатора в сообщении
  (виден только бейдж QUEUE в студии и кнопка «Остановить» в лайтбоксе).
- Промпт карточки — первоклассные данные: карточка хранит `prompt / negativePrompt /
  style / aspectRatio / imageSize / quality`, а `regenerate(item)` в
  `src/ui/gallery-actions.js:152-223` уже гонит `runStage2` с этим снапшотом — но
  **без возможности посмотреть или править промпт**, и с модалкой «те же референсы?»
  на каждый клик.
- Инлайн-задача строит промпт как `prefix + desc + suffix` триггер-профиля
  (`src/inline/triggers.js:135-146`) — Шага 1 (дистилляция сцены текстовой LLM) у
  инлайна и ручной камеры нет.

## 2. Карта класса: как решают те же задачи аналоги

### Семейство sillyimages (оригинал → NSI → SLAY)

Модель сама пишет в ответе `<img data-iig-instruction='{"style":…,"prompt":…}' src="[IMG:GEN]">`;
расширение ловит рендер, ставит заглушку, а после генерации **вписывает путь к файлу
прямо в `message.mes`** (и в swipes/display_text/extblocks), после чего чат
пересохраняется. Пользователь тегов не пишет вовсе.

- **sillyimages**: угловые hover-кнопки Download + Regenerate на каждой картинке;
  собственный лайтбокс (зум 1–5x, пан, навигация по всем картинкам чата) — но без
  действий внутри; error.svg-заглушки с человеческой классификацией ошибок на 8
  категорий + сырьё в tooltip; живой таймер и Stop в заглушке; лорбук-рефы с
  word-boundary матчингом по именам и макросом `{{iig-book}}`; библиотека персонажа;
  дебаг-попап «Show last request» с финальным промптом. Редактирования промпта нет
  вообще; перегенерация **уничтожает картинку в сообщении** (файл остаётся на диске,
  но в чате не виден).
- **notsosillynotsoimages (NSI)**: + кнопка Download, Stop в заглушке с abort
  повторным кликом и **восстановлением прежней картинки после Stop**; smart-подсказки
  при ошибках (второй тост «404 → смените тип API…»); теги видео `[VID:GEN]`;
  тумблер «тег против UI» (prompt-driven); Per-chat скоуп референсов; low-power mode.
  Лайтбокс без зума и только на десктопе.
- **SLAYimages**: гардероб с AI-описанием одежды через отдельный дешёвый API,
  `OUTFIT LOCK` в контексте LLM (depth=0) + текст аутфита в image-промпт по name-gating;
  мобильный лайтбокс с pinch-zoom 1–6x и elementsFromPoint-fallback; слой
  самозаживления чата (src-remap, heal-проходы, детект прерванных генераций);
  принцип «ошибка не затирает живую картинку»; оверлей перегенерации с таймером
  поверх старой картинки.

### Встроенный SD-экстеншен (ядро)

Совсем другой класс: картинка всегда **отдельным сообщением** с media-вложением
(`extra.media[]`, title = промпт). Сильные ходы:

- **Refine-попап** «Review and edit the prompt» (+ negative) перед генерацией,
  глобально или точечно; перегенерация снова проходит через попап от сохранённого
  промпта — цикл «посмотрел → поправил → перегенерировал».
- **Перегенерация = вариант**: новое вложение пушится в `extra.media[]`, старые
  доступны свайпами со счётчиком «1/N» прямо в сообщении; overswipe вправо =
  новая генерация. История не теряется никогда.
- Семь семантических режимов wand-меню («Send me a picture of: Yourself / Face / Me /
  Whole Story / Last Message / Background») с авто-подбором ориентации под режим.
- Отменяемость везде: non-blocking тост со Stop, повторный клик по busy-кнопке = abort.
- Видимость результата для AI — отдельные тумблеры per-инициатор.
- Слабости: нет инлайна в реплике (результат всегда в конце чата), interactive mode —
  хрупкий регекс по сообщению пользователя, конфигурационный ад ~25 источников.

### Autopilot (выбор из N)

Модель пишет `<pic prompt="…">`, расширение открывает **модальный live grid**:
слоты заполняются параллельно (concurrency 1–8, батчи по модельной очереди),
пользователь выделяет лучшие и жмёт «Keep Selected (N)». Внутри же: Edit Prompt
(textarea, живой `editedPrompt`) и **AI-rewrite промпта** (отдельный профиль LLM,
переключение connection-профилей), Regenerate All / Regenerate Selected / Retry Failed
с кнопками, появляющимися по состоянию, лайтбокс с клавиатурой/тач-свайпами и
select-кнопкой. Вставка — media-галереей в сообщение.

### st-image-auto-generation (максимальная автоматизация)

Ноль UI: инжект-инструкция учит модель писать `<pic>` «по битам», генерация стартует
**в момент закрытия тега прямо во время стрима** (не дожидаясь конца ответа), теги
«спасаются» из `<think>`, вставка race-safe (проверка объекта-цели и наличия тега
перед правкой), статусы машины в публичных JS-мапах для сторонних вьюеров. Результата
нельзя выбрать/перегенерировать/поправить — философия «set and forget».

## 4. Что URIS уже делает лучше класса

1. **Текст чата неприкосновенен.** Всё семейство sillyimages вписывает пути файлов в
   `message.mes` — контекст модели загрязняется, ветки/свайпы ломаются, SLAY вынужден
   тянуть целый heal-слой (src-remap, прерванные генерации). URIS решает это
   архитектурно: DOM-оболочки + `chatMetadata` + нативная галерея.
2. **Лайтбокс с действиями.** Только у URIS (и Autopilot в гриде) просмотрщик —
   рабочий инструмент (копировать/кроп/в референсы/реген/удалить), а не просто зум.
3. **Контроль расходов.** cap маркеров, серийный автолейн, «второй платный запрос не
   отправляется, пока не доказано, что первый не дошёл», чеки платных запросов в
   диагностике — аналоги этого класса проблем просто не видят.
4. **Двухэтапный пайплайн** со сборкой промпта из сцены и правкой до оплаты — у
   инлайн-семейства промпт целиком на совести LLM-таггера.
5. **Инфраструктура доставки** (CORS auto-heal, диалекты шлюзов, сверка пропорций) —
   вне конкуренции, ни у кого ничего похожего нет.
6. «Ошибка не затирает живую картинку» — уже реализовано (`runner.js:260`), в классе
   это редкость (SLAY/NSI пришли к этому через багрепорты).

## 5. Дыры UX URIS относительно класса

1. **Промпт нельзя увидеть/править при перегенерации.** `regenerate()` шлёт сохранённый
   промпт вслепую. Запрошенная пользователем фича «редактирование промпта прямо в
   лайтбоксе» — никем из живых конкурентов в просмотрщике не реализована (ближайшие:
   refine-попап ядра, Edit Prompt в диалоге Autopilot). Данные уже на карточке —
   не хватает только модалки.
2. **Нет кнопки «Скачать»** в лайтбоксе (у sillyimages/NSI есть; на мобиле правый клик
   недоступен).
3. **Реролл готовой картинки невидим** — гарды store/store.js:78 оставляют старую
   картинку без единого признака работы в чате. SLAY решает оверлеем с таймером, NSI —
   Stop + откат к прежней.
4. **Pending-заглушка без таймера** — «Генерирую…» и всё; в классе живой `m:ss` уже
   стандарт, и он реально снимает «а оно живо?».
5. **Ошибки инлайна без классификации**: сырой текст в строке-оболочке. У sillyimages —
   8 категорий + совет, у NSI — подсказки-фиксы. В URIS классификатор уже существует
   (`classifyError` в bridge-поверхности) — не вынесен на оболочки.
6. **📷-кнопка шлёт сырой текст поста** (до 4000 символов) как промпт — без Шага 1.
   Для длинной RP-посты это плохой image-промпт; студийный «Строить промпт» тут богаче.
7. **Нет истории вариантов на месте**: перегенерация создаёт новую карточку в галерее,
   но слот/лайтбокс не дают переключиться на предыдущую (ядро решает свайп-галереей
   «1/N»).
8. **Модалка «те же референсы?» на каждый реген** — фрикция при серии реролов.
9. Маркеры внутри `<think>` reasoning-моделей не хоистятся; прегенерации во время
   стрима нет (у st-image-auto-generation есть оба).

## 6. Рейтинг улучшений

Формат: что → зачем → где → оценка. У1–У3 образуют один релизный пакет «лайтбокс».

**У1. Правка промпта в лайтбоксе (edit → перегенерировать).** Кнопка рядом с
«Перегенерировать»: модалка с textarea (промпт карточки), негативом и аспектом →
`runStage2(item.sourceMsgId, {prompt, aspectRatio…}, opts)` — контракт уже такой, как
нужен (`gallery-actions.js:185`). Закрывает дыру №1 и главный запрос пользователя;
делает URIS первым в классе с «промптом в просмотрщике». Усилие: малое-среднее.
Эффект: максимальный.

**У2. Кнопка «Скачать».** Blob-download + на мобиле фолбэк «открыть в новой вкладке»
(как NSI). Усилие: малое. Эффект: большой для мобилы.

**У3. Видимая регенерация.** Во время реролла готовой картинки — полупрозрачный оверлей
со спиннером и живым таймером поверх изображения (reconcile уже видит
`state.activeGenerations`; сопоставление по msgId+idx+type); тот же таймер — в
pending-заглушке. Плюс кнопка Stop на оверлее (abort живого requestId — механика
`cancelPending` уже есть). Закрывает дыры №3–4. Усилие: среднее. Эффект: большой.

**У4. Человеческие ошибки на оболочках.** Прогонять `errorText` через классификатор:
дружелюбный заголовок в строке («Лимит запросов — подождите минуту»), сырьё и совет —
в `title`/tooltip, клик — retry. Плюс одноразовая подсказка-фикс в стиле NSI
(антидубль 30 с). Усилие: малое-среднее. Эффект: средний, сильно снижает «почему не
работает».

**У5. Варианты на слоте.** При перегенерации хранить цепочку cardId (schema v2 слота:
`history: [...]`); в лайтбоксе счётчик «вариант 2/N» и стрелки по истории; в галерее
карточки уже связаны `sourceMsgId`. Референс — `extra.media[]` + `media_index` ядра.
Усилие: среднее. Эффект: большой (сравнение «до/после» без потери результатов).

**У6. 📷-кнопка со Шагом 1 (опционально).** Тумблер «Камера: строить промпт»: клик →
Шаг 1 по тексту поста (шаблон «ключевой момент сцены») → превью-правка → Шаг 2;
вручную — как сейчас. Референс — режимы ядра + refine-попап. Усилие: среднее.
Эффект: большой для качества картинок с длинных постов.

**У7. «N вариантов → выбери» для маркера.** Мини-грид Autopilot, вписанный в
философию URIS: серийно через автолейн (не параллельно), кап-совместимо, выбор в
лайтбоксе. Усилие: большое. Эффект: разрыв с классом, но дорогой по токенам —
после У5.

**У8. Стриминг-прегенерация + хоистинг из `<think>`.** Генерация по закрытому маркеру
во время стрима (с учётом открытого `<think>`); спасение маркеров из reasoning-блока.
Усилие: среднее. Эффект: latency + надёжность на reasoning-моделях.

**У9. Мелкая гигиена.** Запоминать ответ «те же референсы» на сессию (или чекбокс
«больше не спрашивать»); промпт в `title` готовой картинки (как `Style:\nPrompt:` у
sillyimages) рядом с текущим «клик: просмотр»; навигация лайтбокса по всем готовым
картинкам видимого чата (сейчас — в пределах поста). Усилие: малое.

### Что сознательно не копировать

- **Мутацию `message.mes`** путями к файлам (всё семейство sillyimages) — анти-паттерн:
  пути уезжают в контекст модели, ломаются свайпы/ветки, нужен heal-слой.
- **Внешние `error.svg`** (NSI/SLAY-наследие) — точка отказа 404; URIS-подход с
  DOM-оболочкой правильный.
- **Регекс-триггеры interactive mode** ядра — хрупко и без лимитов.
- **Отказ от мобильного лайтбокса** (NSI) — PhotoSwipe уже решает.

### Порядок

У1 + У2 + У3 («лайтбокс-пакет») → У4 + У9 (гигиена) → У5 (варианты) → У6 (камера со
Шагом 1) → У8 → У7.
