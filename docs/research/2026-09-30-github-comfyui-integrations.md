# Опыт интеграций ComfyUI с SillyTavern и клиентскими библиотеками

> Исследование от 2026-09-30 (агент, все репозитории проверены на существование; код ядра SillyTavern прочитан напрямую, release-ветка). Черновик к фиче «ComfyUI как провайдер UR Image Studio».

## (a) Релевантные репозитории и их подходы

### Ядро SillyTavern (эталонная реализация)

**[SillyTavern/SillyTavern](https://github.com/SillyTavern/SillyTavern)** — ComfyUI поддерживается **нативно** встроенным расширением Image Generation. Код:

- клиент: `public/scripts/extensions/stable-diffusion/index.js` (~6000 строк, функции `generateComfyImageCommon`, редактор workflow с плейсхолдерами);
- сервер: `src/endpoints/stable-diffusion.js`, роутер `/api/sd/comfy/*`.

Подход: **проксирование через Node-сервер ST** (браузер вообще не ходит на ComfyUI → CORS не возникает). Workflow хранится как файл в `data/<user>/comfyworkflows/*.json` (API-формат), параметры подставляются **строковым replaceAll по кавычкам**: `" %prompt%"`, `" %negative_prompt%"`, `" %seed%"`, `" %denoise%"`, `" %clip_skip%"`, плюс `%model%/%sampler%/%scheduler%/%steps%/%scale%/%width%/%height%/%vae%`, `%"user_avatar%"`/`%"char_avatar%"` (base64 для img2img) и **пользовательские кастомные плейсхолдеры** (`comfy_placeholders` — find/replace). Генерация: `POST /prompt` → поллинг `GET /history/{id}` каждые 100 мс (**без websocket**) → первый `images[]` из `outputs` (есть фолбэк на `gifs` для видео-нод) → `GET /view?filename=&subfolder=&type=` → отдаёт браузеру base64. Отмена: закрытие сокета запроса → `POST /interrupt`. Списки моделей/сэмплеров/шедулеров/VAE парсятся из **полного `/object_info`** с хардкодом классов нод (`KSampler`, `CheckpointLoaderSimple`, `UNETLoader`, `UnetLoaderGGUF`, `VAELoader`). Отдельная ветка `comfyrunpod` для serverless (`/cancel/{jobId}` вместо `/interrupt`).

### Сторонние ST-расширения (браузер → ComfyUI напрямую)

- **[mozophe/ST-ComfyUI-Imagine](https://github.com/mozophe/ST-ComfyUI-Imagine)** (активен, 2026) — лучшая современная референс-реализация прямого браузерного доступа: `fetch` прямо на `http://127.0.0.1:8188`, `GET /object_info/LoraLoader` для списка LoRA, `/system_stats` как ping, `POST /prompt` → поллинг `/history/{id}` с AbortSignal → сборка `/view`-URL с `encodeURIComponent` и **ручным разбиением subfolder по слэшам** (комментарий в коде: иначе `/view` отдаёт 404), картинка перекачивается в ST через `/api/images/upload`. Мостит SlashCommandAbortController ST в нативный AbortController. **README с обстоятельным разделом про CORS** (см. грабли №1).
- **[lumingya/ST-Comfyui-Simplified](https://github.com/lumingya/ST-Comfyui-Simplified)** (428 строк) — упрощение конфигурации до «экспорт API-JSON → импорт → вписать ID нод» (вход — CLIPTextEncode, выход — SaveImage/PreviewImage с автопоиском). Полезен как каталог антипримеров (см. №5, №7).
- **[TTWParty/SillyTavern-RBQ-Draw](https://github.com/TTWParty/SillyTavern-RBQ-Draw)** (активен, 2026) — китайский плагин рисования с несколькими бэкендами (NAI/ComfyUI/внешние API); бандл минифицирован.
- **[LenAnderson/SillyTavern-ComfyUI](https://github.com/LenAnderson/SillyTavern-ComfyUI)** — исторический (окт 2023 – дек 2023, мёртв): форк SD-расширения под ComfyUI, ходил в ComfyUI прямо из браузера до того, как это попало в ядро. Показателен: когда нативная поддержка появилась, форк умер — поддержка отдельным форком целого расширения нежизнеспособна.

### Клиентские библиотеки ComfyUI

- **[StableCanvas/comfyui-client](https://github.com/StableCanvas/comfyui-client)** (`@stable-canvas/comfyui-client`) — главная JS/TS-библиотека, Node+Browser, zero-deps: полный REST+WebSocket, программный интерфейс `Workflow` (сборка графа кодом), `enqueue` (по WS) **и** `enqueue_polling` (чистый REST), `interrupt()`, `fetchApi()`, транпайлер workflow-JSON → код. Важный issue №22 — см. грабли №3.
- **[Chaoses-Ib/ComfyScript](https://github.com/Chaoses-Ib/ComfyScript)** — Python-фронтенд: workflow как код, транпиляция UI-JSON ↔ скрипт. Отталкивается от канонического запроса «человекочитаемый формат workflow» [comfyanonymous/ComfyUI#612](https://github.com/comfyanonymous/ComfyUI/issues/612).
- **[zombieyang/sd-ppp](https://github.com/zombieyang/sd-ppp)** (~2.2k звёзд, активен) — мост Photoshop ⇄ ComfyUI. Архитектурно другой путь: кастомная нода внутри ComfyUI + websocket-канал — картинки гоняются через спец-ноды `LoadImage`/`PreviewImage`-заменители, клиенту не нужно знать граф.
- **`@saintno/comfyui-sdk`** (npm, репо [tctien342/comfyui-sdk](https://github.com/tctien342/comfyui-sdk)) — TS SDK, последняя публикация **октябрь 2024**, фактически заброшен.
- **Анти-находка:** npm-пакет **`comfy.js` — это НЕ ComfyUI**. Репо [instafluff/ComfyJS](https://github.com/instafluff/ComfyJS) — библиотека для Twitch-чата; в коде нет ни `/prompt`, ни `/ws`. Частая путаница при выборе библиотеки.

### Документация API

## (b) Топ-10 граблей с доказательствами

**1. CORS: из коробки ComfyUI блокирует браузер с другого origin — даже на той же машине.** ComfyUI без флагов вешает `origin_only_middleware`, который отдаёт 403 любому запросу с `Sec-Fetch-Site: cross-site` и молча (без логов!) режет несовпадение Host/Origin: [Comfy-Org/ComfyUI#16203](https://github.com/Comfy-Org/ComfyUI/issues/16203), [artokun/comfyui-mcp-panel#2044](https://github.com/artokun/comfyui-mcp-panel/issues/2044) («silently... genuinely confusing debugging experience»). У ST-расширений это грабля №1 поддержки: «curl работает, а расширение — нет» — [README mozophe](https://github.com/mozophe/ST-ComfyUI-Imagine): `--enable-cors-header` обязателен **даже когда ComfyUI и ST на одном компьютере** (разные порты = разные origin). Флаг заменяет origin-проверку на CORS-заголовок, т.е. отключает CSRF-защиту. Ядро ST поэтому вообще не ходит из браузера — только через серверный прокси. В Docker проброс `*` в `--enable-cors-header` — отдельная боль с кавычками: [YanWenKun/ComfyUI-Docker#190](https://github.com/YanWenKun/ComfyUI-Docker/issues/190).

**2. Медленный `/object_info`.** Полный `/object_info` сериализует все зарегистрированные ноды; с кастомными паками ответ — мегабайты и минуты: [Comfy-Org/ComfyUI#9131](https://github.com/Comfy-Org/ComfyUI/issues/9131) («object_info response is taking over a minute»); тяжёлые `INPUT_TYPES()` у кастомных нод блокируют ответ. Ядро ST — антипример: он тянет **полный** `/object_info` четыре раза подряд (samplers, models, schedulers, vaes — `src/endpoints/stable-diffusion.js`, строки 403–483). Правильно — точечный `GET /object_info/{node_class}` (как делает mozophe: `/object_info/LoraLoader`).

**3. WebSocket: потеря/перепутывание событий при длинной истории.** [StableCanvas/comfyui-client#22](https://github.com/StableCanvas/comfyui-client/issues/22): при одном `client_id` и выросшем `/history` события `executing`/`executed` теряются или приходят не в том порядке — клиент не может понять, какому промпту принадлежит картинка. Статус: открыт, `help wanted`/`wontfix` (чинить надо на сервере). Подтверждённые воркараунды: **новый client_id на каждый запрос** и очистка истории после задачи (`clearItems('history')` — заодно помогает с памятью). Итог: WS — не бесплатная победа; поллинг `/history/{id}` проще и надёжнее, что ядро ST и подтверждает (оно WS не использует вовсе).

**4. Переподключение websocket за прокси.** [caru-ini/modal-comfyui#14](https://github.com/caru-ini/modal-comfyui/issues/14) → фикс в [#15](https://github.com/caru-ini/modal-comfyui/pull/15) (фильтрация заголовков при рестарте WS). Если идти по пути WS — закладывать реконнект + сверку с `/queue`/`/history` после реконнекта.

**5. Поллинг без таймаута / с глотанием ошибок.** Антипримеры из реального кода: ядро ST — `while(true) { fetch(history); delay(100); }` **без ограничения по времени** ([src/endpoints/stable-diffusion.js:590](https://github.com/SillyTavern/SillyTavern/blob/release/src/endpoints/stable-diffusion.js)); lumingya — `setInterval` 1000 мс, жёсткий лимит 600 итераций с неинформативным «超时», и **пустой `catch(e) {}`**, глотающий сетевые ошибки ([index.js:394–428](https://github.com/lumingya/ST-Comfyui-Simplified/blob/main/index.js)). Учится наоборот у ST: он парсит `history[id].status.messages` → `execution_error` и показывает `node_type [node_id] exception_type: exception_message`.

**6. «Промпт выполнен, а картинки нет».** Причины из практики: (а) в workflow нет `SaveImage`/`PreviewImage` → `outputs` пуст → ошибка ST «ComfyUI did not return any recognizable outputs»; (б) `PreviewImage` пишет в **temp**, а не output — `/view` без `type=temp` даёт 404, temp чистится при рестарте ([гайд ViewComfy](https://www.viewcomfy.com/guides/what-is-comfyui-api), [ComfyUI_frontend#4091](https://github.com/Comfy-Org/ComfyUI_frontend/issues/4091)); (в) subfolder с вложенными путями: mozophe держит в коде комментарий «/view needs them split, with forward-slash subfolder. ...or /view 404s» ([index.js:1181–1194](https://github.com/mozophe/ST-ComfyUI-Imagine/blob/main/index.js)). Всегда брать `filename/subfolder/type` из ответа history, а не конструировать самому.

**7. Хрупкость маппинга workflow (API-формат, ID нод).** Весь смысл lumingya-плагина — «заполни ID нод вручную, потому что у всех графы разные»; их FAQ: перепутал ID входной ноды → «картинка вся в шумах/чёрная». При правке графа в ComfyUI ID нод меняются — конфиг молча ломается. Второй слой той же проблемы: юзеры экспортируют **не тот** формат (Save вместо Save (API Format), включённый Dev Mode) — это повторяется в README всех расширений. И даже в ядре: дефолтный `Default_Comfy_Workflow.json` вышел с битым графом (нет VAE-лоадера) — [SillyTavern#2322](https://github.com/SillyTavern/SillyTavern/issues/2322): поставляемый дефолтный workflow надо тестировать.

**8. Подстановка плейсхолдеров: тихие отказы.** ST подставляет только **квоченные** плейсхолдеры (`'"%prompt%"'` → `JSON.stringify(prompt)`) — если пользователь вставил `%seed%` без кавычек или в числовое поле не тем типом, замена тихо не происходит и ComfyUI получает мусор или валидирует ошибку. Плюс типизация: PR [SillyTavern#3088](https://github.com/SillyTavern/SillyTavern/pull/3088) вскрывает, что base64 для img2img приходилось чистить от data-URL (`data:image/png;base64,`), потому что ноды-лоадеры его не принимают, и что до этого «0 people have got this to work». Урок: плейсхолдеры должны быть строковыми по определению, binary — отдельным механизмом, а перед отправкой стоит валидировать, что все известные плейсхолдеры реально заменились.

**9. Аутентификация и безопасность при удалённом доступе.** ComfyUI не имеет токен-аутентификации — единственная защита по умолчанию это origin-middleware, который `--enable-cors-header` выключает ([анализ в AtlasCloud PR #111](https://github.com/AtlasCloudAI/atlascloud_comfyui/pull/111): «ComfyUI ships no token auth... that middleware is skipped under --enable-cors-header»). Облачные ComfyUI-хостинги решают это `?token=` в URL — и ядро ST это не поддерживает, потому что `new URL(urlJoin(url, '/prompt'))` **теряет query-строку**: [SillyTavern#4146](https://github.com/SillyTavern/SillyTavern/issues/4146). Урок: хранить базовый URL и query-параметры раздельно, а `--listen 0.0.0.0` без понимания не советовать.

**10. UX-мелочи, которые реально бесят.** Невозможность переименовать импортированный comfy-workflow (только удалить и перезалить) жила в ядре ST до 2026-02 — [SillyTavern#5120](https://github.com/SillyTavern/SillyTavern/issues/5120). Генерик «API 连接失败，请检查 URL 和跨域设置» у lumingya маскирует под одной надписью и CORS, и таймаут, и ошибку валидации графа (`POST /prompt` возвращает 400 с `node_errors`/«Prompt outputs failed validation» — это надо распарсить и показать ноду). Также: отмена без `/interrupt` (mozophe абортит fetch, но ComfyUI продолжает считать задачу) — «отмена» должна означать `POST /interrupt`, иначе очередь забивается.

## (c) Дизайн-рекомендации для UR Image Studio (браузерное JS-расширение → локальный ComfyUI)

1. **Транспорт: решите между прокси и прямым fetch осознанно.** Вариант А (как ядро ST): маленький серверный плагин-прокси — ноль проблем с CORS, картинка приходит base64. Вариант Б (как mozophe): прямой `fetch` на `localhost:8188` — не требует серверной части, но обязан требовать `--enable-cors-header`. В обоих случаях: **детектируйте 403/CORS-сбой и показывайте инструкцию с точным флагом** («curl работает, браузер нет» — главный симптом). Проверка соединения — `GET /system_stats` (дёшево и без side-эффектов).

2. **Workflow: API-формат JSON + квоченные плейсхолдеры (паттерн ST).** Храните workflow текстом, подставляйте `'"%prompt%"' → JSON.stringify(...)` — кавычки гарантируют, что заменяются только строковые поля. Набор: `%prompt%`, `%negative_prompt%`, `%seed%`, `%width%/%height%`, `%steps%`, `%cfg%`, `%sampler%`, `%scheduler%`, `%model%`, `%denoise%`, плюс **пользовательские кастомные плейсхолдеры find/replace на каждый workflow**. Перед отправкой валидируйте: все ли известные плейсхолдеры заменились, есть ли в графе `SaveImage`/`PreviewImage` и `CLIPTextEncode` — и показывайте список найденных `class_type` (быстрая диагностика «не тот формат JSON»).

3. **Альтернатива/дополнение — маппинг нод по назначению, а не по жёсткому ID**: авто-поиск первой `CLIPTextEncode` без входящих связей текста (вход) и первого `SaveImage`/`PreviewImage` (выход), с ручным оверрайдом ID, как у lumingya/mozophe. Не хардкодьте классы жёстко: у Flux/Kohya графы другие (`UNETLoader`, `KSamplerAdvanced`, несколько `CLIPTextEncode`) — берите пример с серверного кода ST, где `UnetLoaderGGUF` читается через optional chaining.

4. **Очередь: `POST /prompt` + поллинг `/history/{id}` как база** (так делает ядро ST; достаточно для UI-студии), WS — опционально для прогресса. Если берёте `/ws`: **уникальный `client_id` на запрос** и очистка history после забора результата (урок StableCanvas#22), реконнект с восстановлением состояния из `/queue`+`/history`. Прогресс: события `progress {value,max}` по WS; при поллинге — честный «в очереди» из `/queue`.

5. **Поллинг: интервал 300–1000 мс, настраиваемый таймаут** (не `while(true)` как у ST, не молчаливые 600 тиков как у lumingya), AbortController от UI, отмена = `abort()` fetch **+ `POST /interrupt`**.

6. **Ошибки — из history, не свои придумывайте**: `status.status_str === 'error'` → соберите `status.messages` типа `execution_error` в строку `node_type [node_id] exception_type: exception_message` (формула ST). `POST /prompt` не 200 → распарсите тело: там `error` + `node_errors` с валидацией по нодам — покажите конкретную ноду, а не «ошибка соединения».

7. **Картинки**: из `history[id].outputs` возьмите `images[]` (`filename/subfolder/type`) — поддержите также `gifs`/`videos` (видео-ноды); `/view?filename=...&subfolder=...&type=...` со всеми тремя параметрами и `encodeURIComponent`, subfolder передавайте как есть (ST передаёт целиком). Сразу копируйте картинку к себе (base64/загрузка в ST), не оставляйте ссылку на `/view`: temp чистится, а удалённый ComfyUI — недоступен.

8. **Списки моделей/LoRA/сэмплеров**: точечные `GET /object_info/{node_class}` (`CheckpointLoaderSimple`, `UNETLoader`, `UnetLoaderGGUF`, `LoraLoader`, `VAELoader`, `KSampler`), кэшируйте с кнопкой «обновить» (ноды ставятся на ходу), отсутствующий класс = пустой список с подсказкой, не ошибка.

9. **Безопасность**: по умолчанию советуйте `--enable-cors-header *` **только локально** и предупреждайте, что флаг снимает CSRF-защиту (любой сайт в браузере сможет дёргать ComfyUI); `--listen 0.0.0.0` — только с явным предупреждением. Поддержите базовый URL с сохранением query-параметров (для облачных хостингов с `?token=`) — не наступайте на грабли ST#4146.

10. **Не используйте npm `comfy.js`** (это Twitch-чат) — если нужна готовая клиентская логика, референсы: `@stable-canvas/comfyui-client` (живая, browser-ready) или просто скопируйте ~150 строк логики из `src/endpoints/stable-diffusion.js` ядра ST — это минимальный проверенный боем набор (ping/prompt/poll/view/interrupt/object_info).
