# Улучшение comfy-провайдера URIS: сравнение с аналогами и план

> От 2026-10-01. Синтез двух исследований: [конфигурация Comfy в ST-экосистеме](2026-10-01-comfy-config-ux-st-ecosystem.md) и [паттерны workflow-как-продукт](2026-10-01-workflow-as-product-patterns.md). Принцип — пет-проект: без оверинжиниринга (см. «Ревизию» в [синтезе фичи](2026-09-30-comfyui-in-uris-synthesis.md)).

## 1. Где URIS среди аналогов

Текущая реализация: контракт `comfyui`, встроенные txt2img/img2img-дефолты, плейсхолдеры `%prompt%/%seed%/%model%/%width%/%height%` по конвенции ядра ST, валидация до отправки, ошибки по нодам, референсы через `/upload/image` → LoadImage по возрастанию ID, ручной ввод чекпойнта, кнопка «Проверить» для comfy мертва.

| Возможность | URIS | Лучшие в поле |
|---|---|---|
| Встроенные дефолтные workflow | **✓ txt2img + img2img-на-референсах, покрыты тестами** | ST ядро (2 пресета; их дефолт исторически выходил битым, #2322) |
| Плейсхолдеры | **✓ та же конвенция, что у ядра; промпт — последним; split/join ≡ replaceAll** (защита от #2460) | ST ядро: + кастомные find/replace, ST-макросы |
| Валидация до отправки | **✓✓ самая полная в выборке**: JSON-parse, выходная нода, %prompt%, подсчёт LoadImage против числа референсов, детект UI-формата | RBQ-Draw/Bridge — близко, но после нас |
| Ошибки | ✓ node_errors + execution_error по нодам; **✗ без class_type-фолбэка** | Bridge/ST-сервер: `узел [3] (KSampler)` |
| Список моделей с сервера | **✗ ручной ввод, «Проверить» не работает** | ST ядро (чекпойнты+UNet+GGUF одним /object_info), RBQ-Draw, ECG |
| Живая обратная связь по workflow | **✗ только текст-плейсхолдер в подсказке** | ST ядро: ✅/❌ индикатор плейсхолдеров в редакторе |
| Авто-распознавание нод | частично (LoadImage по возрастанию ID) | RBQ-Draw (топология+эвристики+отчёт), Bridge (обход графа от KSampler) |
| Настройка без правки JSON | **✗** | Imagine (титулы IMAGINE_*), RBQ-Draw (алиасы+дропдауны), ViewComfy (форма из скана) |
| Пресеты workflow | ✗ (один на подключение) | у всех |
| Импорт из PNG-метаданных | ✗ | RBQ-Draw |
| Референсы | **✓ upload → LoadImage — единственные в выборке** | Imagine — только LoRA-титулы |
| Доставка direct/proxy с автообучением | **✓✓ уникально** | все остальные требуют прямой доступ + CORS-флаг |

**Вывод:** URIS впереди выборки по надёжности (валидация, дефолты, референсы, доставка), но **отстаёт ровно в двух точках первого контакта**: «где взять список моделей» и «правильно ли я вставил workflow». Обе лечатся дёшево, потому что инфраструктура уже есть (probe-машинария, `parseAndValidateWorkflow`).

## 2. Улучшения

### Ярус 1 — сделать сейчас (суммарно ~пол-вечера)

**У1. «Проверить» для comfyui + список моделей в дропдаун.** Ветка в `connect-probe.js`: `GET /system_stats` (ping + версия) → `GET /models/checkpoints` (фолбэк `/object_info/CheckpointLoaderSimple`, `input.required.ckpt_name`) → `modelIds` с `imageGeneration: true` → существующий дропдаун моделей заполняется; `detected.apiShape = 'comfyui'` (новое значение в `API_SHAPES` + строка в `DIALECT_ORDER` — по образцу naistera-ветки). Закрывает боль «нет моей модели в списке» (#3088) и убирает ручной ввод. ~40 строк + тест.

**У2. Живой индикатор под textarea workflow.** Экспортировать из адаптера `summarizeWorkflow(text)` → `{placeholders: {prompt, seed, model, width, height}, outputNode, loadImageCount, clipTextNodes, checkpointLoaderWithoutModelPlaceholder}`; форма на каждый ввод рисует чипы: `%prompt% ✓ · %seed% ✓ · %model% ✗ · выход ✓ · LoadImage: 1` + предупреждение «в графе есть CheckpointLoader, но нет %model% — поле „Модель" не применится» (защита по мотивам RBQ-Draw). Переиспользует `substituteWorkflow`/`parseAndValidateWorkflow`. ~60 строк формы + хелпер + тесты. Это ST-ядренный приём ✅/❌, адаптированный под нашу валидацию.

**У3. class_type в ошибках (S3 из живого прогона).** `COMFY_PROMPT_REJECTED` и `COMFY_EXECUTION_ERROR`: если сервер не дал `node_type`, взять `class_type` из собственного workflow по ID ноды. ~5 строк + тест.

### Ярус 2 — следующая итерация (по желанию)

**У4. Кнопки «Вставить встроенный txt2img / img2img»** рядом с textarea — старт с рабочего графа вместо пустой страницы (паттерн Imagine: «начинайте со своего рабочего графа»). ~20 строк.

**У5. Отчёт-скан при вставке workflow.** Однострочный toast/строка при потере фокуса textarea: «Нод: 7 · промпт: 6 (CLIPTextEncode) · сид: 3 (KSampler) · LoadImage: 10 · выход: 9 (SaveImage)» — мостик к осознанности RBQ-Draw без полного UI маппинга. Строится на хелпере из У2. ~40 строк.

**У6. Пресеты workflow (мульти-workflow) на подключении.** Хранение `workflows: {имя: json}` + выбранный; дропдаун. Имеет смысл, только когда надо переключать стили (SD1.5/SDXL) в рамках одного подключения. Средний объём (миграция поля) — отложить до реальной потребности.

**У7. Импорт workflow из PNG** (RBQ-Draw): чанк tEXt `workflow` в PNG от ComfyUI — обходит ловушку Dev Mode. ~50 строк; мило, не срочно.

### Ярус 3 — сознательно не делаем (анти-оверинжиниринг)

- **Граф-редактор** (ECG/LiteGraph): дорогая зависимость; редактор уже есть в ComfyUI, наша точка интеграции — текст.
- **Полная форма-генерация à la ViewComfy** (автоскан → контролы на каждый инпут): правильный паттерн для продуктов поверх Comfy, но для пет-проекта перебор; 80% пользы даёт У2+У5.
- **Дропдауны маппинга на каждый параметр** (Bridge) и **поиск промпта обходом графа**: окупятся, только когда плейсхолдерная модель начнёт реально мешать. Возврат к теме — при появлении боли «промпт попал не туда» (у нас её нет: подстановка видна в чипах У2).
- **Титул-конвенции** (Imagine) и **input-ноды** (ComfyDeploy) — альтернативные парадигмы, конфликтующие с плейсхолдерной моделью; знать о них достаточно.
- **WS-прогресс, App Mode, DSL-транспайлеры** — вне скоупа (см. прежние решения).

## 3. Рекомендация

Сделать **У1 + У2 + У3** одним заходом (TDD, тесты на хелпер `summarizeWorkflow` и probe-ветку): это закрывает обе точки отставания и наследие живого прогона, не трогая архитектуру. У4/У5 — следующим заходом, если после У1/У2 останется ощущение шероховатости. Остальное — по мере появления реальной боли.

## 4. Статус реализации (2026-10-01)

**У1, У2, У3 и У4 реализованы** (TDD, полный прогон 1461/1461). Что вошло:

- **У1**: ветка `probeComfyConnection` в `connect-probe.js` (по `input.dialect` из формы): `/system_stats` → `/models/checkpoints` (фолбэк `/object_info/CheckpointLoaderSimple`, аннейминг понимает и плоский список 0.38+, и вложенный 0.20.x) → `detected.modelIds` с `imageGeneration: true` → дропдаун моделей. В схему добавлены `apiShape: 'comfyui'` и `auth: 'none'`; в dispatch-plan — `API_SHAPES.COMFYUI`, диалект-цепочка и эвристика порта 8188; в форме — «Проверить» передаёт диалект, строка фактов показывает «без ключа». Проверено вживую против стенда 8188 (DreamShaper 8 найден, delivery direct).
- **У2**: `summarizeWorkflow(text)` в адаптере (голые числовые плейсхолдеры подменяются нулями перед JSON.parse — шаблон и есть невалидный JSON) + живая строка-сводка под textarea: «Промпт ✓ · Seed ✗ (фиксированный) · Выход ✓ · LoadImage: N» + предупреждение «чекпойнт-лоадер без %model%».
- **У3**: `COMFY_PROMPT_REJECTED` и `COMFY_EXECUTION_ERROR` при отсутствии `node_type` от сервера берут `class_type` из собственного workflow по ID ноды.
- **У4**: кнопки «Вставить встроенный txt2img / img2img (референс)» рядом с textarea.

Не делалось (ярус 2–3): пресеты мульти-workflow, импорт из PNG, отчёт-скан при вставке, маппинг-дропдауны, форма à la ViewComfy — см. разделы выше.
