# UX/UI-аудит расширения: плохие дизайнерские решения

Дата: 2026-10-13. Метод: пять параллельных ревью UI-слоя (шелл окна, генерация, галерея/референсы, настройки/подключения, CSS + инлайн-рендер) по чек-листу ui-design-brain. Все находки подтверждены чтением кода; ссылки — `файл:строка`.

**Общий вердикт.** Инженерная дисциплина выше среднего: дизайн-токены в `:root`, документированная z-лестница, восстановление скролла вкладок, подтверждения удалений в большинстве мест, PhotoSwipe с клавиатурой и локализацией. Дизайн-слой проигрывает именно там, где пользователь платит деньги или теряет данные: семантика «Отмены», молчаливое автосохранение, предупреждения в hover-only `title`, тач-таргеты в 2–3 раза меньше нормы.

---

## P0 — риск необратимой потери данных / денег

### 1. «Отмена» в диалоге «Сохранить как референс» запускает перезапись чужой картинки
`src/ui/gallery-actions.js:103-107, 126-133`. Двухальтернативный выбор заложен в OK/Cancel-диалог: «OK» — создать новый референс, «Отмена» — **заменить изображение существующего**. Для пользователя «Отмена» — рефлекс «выйти», а здесь она переключает флоу на перезапись. Сама замена после выбора референса не подтверждается вообще: `updateRef` + `releaseRefImage(oldImage)` выполняются сразу, undo нет. Итого необратимая перезапись за два клика, один из которых пользователь считал отказом. Тот же паттерн — в вопросе про кроп (`gallery-actions.js:111-115`).
**Что делать:** трёхкнопочный диалог («Создать новый» / «Заменить существующий…» / настоящая «Отмена»); перед перезаписью — confirm с именем референса и превью старой картинки или undo-тост.

### 2. «Очистить» в панели INFO стирает страховые записи платных запросов без подтверждения
`src/ui/window.js:572-581`. Ghost-кнопка одним кликом чистит и журнал ошибок, и `clearPendingBrowserRequests()` — те самые «чеки» оплаченных генераций с неизвестным исходом, которые собственные комментарии кода называют «главной страховой функцией». Ни подтверждения, ни undo, ни разделения скоупов. Сравните: в соседней QUEUE-панели «Очистить завершённые» удаляет только done — одинаковые на вид кнопки с несопоставимым радиусом действия.
**Что делать:** разделить на «Очистить журнал» (безопасно) и точечное удаление recovery-записей крестиком на карточке; массовое удаление — с confirm, называющим цену («Удалить 2 записи о неясных платных запросах?»).

## P1 — серьёзные проблемы ключевых сценариев

### 3. Автосохранение коннекта падает молча — правки теряются без сигнала
`src/ui/server-connection-form.js:388-394`. Цепочка `doSave → saveConnection → normalizeConnectionTimeoutMs` бросает `TypeError` при невалидном таймауте (очистил поле — достаточно), весь проход сохранения отвергается, `catch {}` это глотает. API-ключ при этом пишется отдельно и сохраняется — иллюзия «всё сохранилось» полная. Форма выглядит как форма, ведёт себя как автосохранение без обратной связи — худшая комбинация двух моделей.
**Что делать:** inline-валидация on blur; постоянный статус-стрип «Не сохранено: …» на карточке; никогда не глотать исключение полностью.

### 4. Ошибка JSON в «Доп. параметрах» вычисляется, но никогда не показывается
`src/ui/server-connection-form.js:255-259, 287-289`. Строка «Доп. параметры: некорректный JSON» не рендерится нигде; `__extraBodyError` используется только чтобы вернуть сырой текст в textarea. Пользователь с висячей запятой платит за запросы, в которые его параметры молча не попадают. Это не отсутствие валидации — это дезинформация.
**Что делать:** ошибка inline под textarea на blur + подсветка поля.

### 5. Пикер «заменить референс» показывает только первые 9 из всего пула
`src/ui/gallery-actions.js:387-391`. Выбор реализован через custom-кнопки системного попапа ST, которых физически 9; при большем пуле референсы №10+ недостижимы — ни поиском, ни скроллом, без превью. Готовый `showPoolPicker` (сетка с превью, чипы папок, поиск) написан (`tab-references.js:1253`), но этот флоу его не использует.
**Что делать:** использовать `showPoolPicker({ multi: false })`.

### 6. Генерация (платная, десятки секунд) не имеет in-place статуса
`src/ui/tab-generate.js:912-916, 952-955`. Фидбек только исчезающими тостами; единственный признак в экране — появляющаяся/исчезающая кнопка «Остановить» (layout-shift). Отвернувшийся пользователь не узнает ни статус, ни результат, ни позицию в очереди.
**Что делать:** постоянная строка статуса в карточке промпта (спиннер + «Генерация… 12с · 2/3 в очереди»), по завершении — inline-результат с миниатюрой.

### 7. Over-limit референсов: предупреждение без enforcement и без быстрого действия
`src/ui/tab-generate-refs.js:81`. «Выбрано N референсов, маршрут поддерживает M. Удалите лишние» — но «Сгенерировать» не блокируется, а удаление ручное: крестики 18×18px по одному. Либо пользователь платит за генерацию, которая упадёт, либо чистит чипы руками.
**Что делать:** блокировать кнопку при overLimit + действие «Оставить первые M».

### 8. Светлые темы ST ломают читаемость: фон зашит в тёмный, текст — из темы
`style.css:30-45, 193-194`. `background: #1c1c1c` принудительно, `color: var(--SmartThemeBodyColor)` — из пользовательской темы. В светлой теме тёмный текст на тёмном фоне. Расширение декларирует «адаптивность к любой теме», фактически поддерживает только тёмные.
**Что делать:** фиксировать и текст, либо вычислять поверхности через `color-mix` от темы. Смежно: белый текст на адаптивном `--uris-accent` (`style.css:510-512, 789-791`) при светлом акценте даёт 1.5–2.5:1 — вычислять контрастный цвет текста по luminance.

### 9. Контраст и кегль: 9–10px текст цветом #666 (≈3.0:1)
`style.css:87, 45`. `--uris-font-label: 9px`, `--uris-text-dim: #666` на #1c1c1c — ниже WCAG AA даже для крупного текста, а это подписи папок, счётчики, хинты, имена референсов на чипах. Строки ошибок дополнительно приглушены `opacity: 0.85` (`style.css:1823`) — самое важное содержимое панели самое мелкое и полупрозрачное.
**Что делать:** минимум 11–12px для содержательного текста; dim поднять до #8a8a8a+; ошибки — не мельче 13px, полная непрозрачность.

### 10. Тач-таргеты 16–28px массово, включая деструктивные действия
Подтверждено в CSS: крестик удаления референса 18×18 (`style.css:926-940`), удаление папки из чипа 20×20 (`:1393-1397`), свотч цвета 16×16 (`:1480-1482`), отмена задачи очереди ~16×20 (`window.js:603` + `style.css:1835`), закрытие окна ~28×20 (`style.css:217`), FAB = 36px (`floating-launcher.js:28`). Комментарий `style.css:1734-1736` фиксирует осознанный компромисс «22px достаточно» — но 44px (Apple/Google) / 24px минимум (WCAG 2.5.8) это вчетверо меньше нормы. Паттерн «большой прозрачный хит-бокс + маленький глиф» уже применён у кроп-ручек (`style.css:2514-2530`) — он же и есть решение.
**Что делать:** расширять hit-area псевдоэлементом/`inset:-10px` для всех кнопок ≤24px, визуальный размер можно оставить.

### 11. Клавиатурная доступность дырявая при наличии правильных образцов в том же коде
- Инлайн-картинки в чате: голый `<img>` с click (`src/inline/render.js:230-239`) — нет tabindex/роли/Enter. В галерее тот же лайтбокс открывается настоящим `<button>` с комментарием про клавиатуру.
- Аккордеоны вкладки API: click-only на `<h4>` (`accordion-state.js:94-106`) — ни tabindex, ни `aria-expanded`, ни Enter/Space.
- Чипы пресетов кропа — кликабельные `<span>` (`crop-dialog.js:88-93`).
- Лента «Медиа»: `<img>` с click (`tab-media.js:252-258`).
- Force-include референса только drag-and-drop (`tab-generate-refs.js:394-443`), без клавиатурной альтернативы.

**Что делать:** обернуть в `<button>` / дать роль и обработку клавиш — паттерны уже существуют в кодовой базе; политика хелперов должна делать правильный путь единственным.

### 12. Таб-бар: 8 вкладок, скрытый скроллбар, ноль аффорданса переполнения
`tabs.js:91-99`, `style.css:231-235`. Механика доскролла отличная (колесо, drag — `tab-bar-scroll.js`), но визуально бар неотличим от «всё помещается»: ни скроллбара, ни градиентных масок, ни «подглядывания». Пользователь не знает, что «Настройки» существуют. Плюс developer-вкладка «API» стоит первой в порядку, а не «Генерация».
**Что делать:** fade-маска по краю при `scrollWidth > clientWidth`; пересмотреть порядок вкладок под первичную задачу.

### 13. Падение рендера вкладки = пустое тело, фидбек только в дальнем бейдже
`tabs.js:70-76`. Ошибка уходит в консоль и INFO-бейдж в шапке; пользователь видит пустую вкладку без объяснений на месте. Та же болезнь: ошибки генерации вынесены из вкладки в header error pool (`tab-generate.js:146-148`) — вдали от кнопки, её вызвавшей.
**Что делать:** inline error state в теле вкладки с «Повторить»; бейдж — дублирующий канал.

### 14. Disabled primary «Сгенерировать» без объяснения причины
`tab-generate.js:126, 859-864`. Классическая «мёртвая кнопка»: причина (пустой промпт) нигде не сообщается, ветка с тостом «Промпт пуст» недостижима, пока кнопка disabled. Рядом тот же антипаттерн: причина недоступности модели — в `title` disabled select (`tab-generate.js:362, 368`).
**Что делать:** видимая hint-строка под контролом; тост по клику на disabled-обёртку.

### 15. Placeholder заменяет лейбл и инструкцию у главных полей
`tab-generate.js:204` («Промпт картинки» — лейбла нет), `tab-generate.js:154` (placeholder несёт целую инструкцию про распознавание референсов — исчезает при первом символе). Тот же паттерн: «не требуется» как placeholder ключа API для ComfyUI (`server-connection-form.js:215`).
**Что делать:** видимые лейблы; инструкции — статичными hint-строками под полем (образец уже есть: `tab-settings.js:62,72`).

## P2 — заметно ухудшают опыт

16. **Критичные знания о шлюзе заперты в `title`** — семантика Авто/прокси, ~30 минут кэша и **платное** предупреждение «Остановить при прокси не отменяет запрос у провайдера» доступны только по hover; на мобильных — никогда (`server-connection-form.js:229-232`). Смежно: «Промпт никого не упомянул» — только в title плитки «+» (`tab-generate-refs.js:527-529`).
17. **Инлайн-оболочки вставляются в конец сообщения, а не на место маркера** — `render.js:452-462`: raw-текст маркера прячется на месте, картинка появляется внизу поста; при нескольких маркерах все изображения слипаются в колонку, оторванные от контекста. Грамматика возвращает `start/end` (`grammar.js`), рендер их не использует.
18. **Ошибка генерации в чате — нейтральная серая кнопка с сырым текстом провайдера** (`render.js:271-284`): визуально неотличима от «📷 Нарисовать», длинные английские `HTTP 429…` ломают погружение, инструкция «— клик: retry» зашита в текст.
19. **Pending-заглушка не ограничена по высоте** (`style.css:2653-2661` vs `:2619-2622`): для 9:16 заглушка займёт ~747px чата и схлопнется до 420px по готовности — резкий layout-скачок.
20. **Триггер-профили: создание в один клик, удаления нет нигде** (`tab-media.js:108-115`) — каждый клик «＋ Свой тип» добавляет необратимый мусорный профиль; grep по `removeTrigger` пуст.
21. **Тестовый стенд: платную генерацию можно запустить дважды** — кнопка «Сгенерировать» не блокируется на время `await queueInlineJob` (`tab-media.js:204-225`); in-flight guard есть у `regenerate`, здесь забыли.
22. **Диалоги без Escape и клика по фону**: batch-загрузка во время прогона — ловушка («Отмена» disabled, Escape не работает — `ref-batch-upload.js:121-141, 182`); `showPoolPicker` игнорирует клики по фону (`tab-references.js:1261-1337`). В остальных диалогах Escape есть — непоследовательно.
23. **`aria-modal="true"` без управления фокусом**: crop-диалог (`crop-dialog.js:76-78`) — фокус не переносится, Tab не зациклен, возврата нет; редактор референса (`tab-references.js:676-679`) — `aria-modal` на немодальной боковой панели, Escape не закрывает. `role="dialog"` на немодальных QUEUE/INFO-панелях (`window.js:54-55`).
24. **«Сбросить знания о шлюзе» — деструктив без подтверждения** (`server-connection-form.js:238, 460-465`): стирает каталог моделей и память доставки одним кликом, тогда как удаление коннекта/галереи/шаблона подтверждается. Политика непоследовательна.
25. **Удаление карточки в мосте без подтверждения** (`tab-bridge.js:269-277`); **«Остановить очередь»** отбрасывает пачку задач одним кликом (`window.js:613-618`).
26. **Карточка галереи: постоянный ряд из 5 серых иконок 24px** (`tab-gallery.js:69-75`, `style.css:701-702`): «Удалить» не выделена (в меню она красная — рассинхрон), визуальный шум на сетке из сотен карточек. Показывать по hover или свернуть в «⋯» (меню уже есть).
27. **Ошибка загрузки профилей отрисована как пункт выпадающего списка** (`tab-api.js:137-139`) — «Ошибка загрузки профилей» как выбираемый option, без причины и «Повторить».
28. **QUEUE-панель сбрасывает скролл и пересоздаёт DOM под курсором** (`window.js:591-635`) — INFO-панель рядом скролл честно сохраняет; кнопка «Повторить» может исчезнуть из-под курсора в момент клика.
29. **Idle-бейдж QUEUE выглядит disabled именно когда в нём «Повторить»** (`window.js:649-661`) — бейдж тускнеет при нуле живых задач, но лента помнит упавшие.
30. **Смешение языков и жаргон в UI**: лейблы «QUEUE»/«INFO» (плюс нарушение Label-in-Name: `aria-label` не содержит видимого лейбла, `window.js:547-551`), «Stage 1 / Stage 2 распознано» (`tab-generate-refs.js:271-274`), «Стороны» / «Quality» / сырые API-значения в опциях (`tab-generate.js:219-229, 311`), английские сообщения валидации в русском UI (`server-connection-form.js:348-352`), dev-строки в тостах (`tab-templates.js:36, 186`).
31. **Фокус не возвращается в лаунчер при сворачивании окна** (`window.js:377-382`) — для бейдж-панелей возврат сделан, для самого окна нет. Смежно: Esc сворачивает окно только при фокусе внутри (`window.js:388-392`) — открыл через FAB → Esc не работает.
32. **Esc-слой держится на селекторном белом списке** одного оверлея (`window.js:399`) — любой будущий оверлей без класса `uris-picker-overlay` получит «Esc закрыл оверлей И свернул окно». Нужен общий стек модальности.
33. **Пустые состояния — голые однострочники без CTA** (`tab-gallery.js:134-136`, `tab-references.js:646, 953`, `tab-media.js:249`): нет ни заголовка, ни кнопки действия. Empty state постнавигации — объяснение заперто в placeholder disabled-поля (`tab-generate.js:272`).
34. **Вложенные скроллы в picker-диалоге на десктопе** (`style.css:1640, 1646-1649`): диалог скроллится сам + сетка 55vh внутри + список 46vh. Мобильный вариант уже решён правильно (`style.css:1700-1718`) — десктоп забыли. Нет `overscroll-behavior: contain` у панелей.
35. **Референсы на десктопе: фиксированные 170px + 260px схлопывают сетку** при ширине окна 320–430px (`style.css:1088-1094, 1299-1305` vs `:184`) — центральная сетка получает нулевую ширину без скролла и сигнала.
36. **Кнопки include/exclude у кандидатов не показывают текущее состояние** (`tab-generate-refs.js:139-140`) — нет `aria-pressed`, иконка «ban» как «исключить» раскрыта только в title.
37. **Hover-only деструктивные действия без тач-эквивалента** — удаление шаблонов/коннектов краснеет только на hover (`style.css:654-660, 427-433`); на тач кнопка навсегда выглядит приглушённым текстом.
38. **Упавшая ручная генерация не имеет «Повторить»** (`queue-log.js:33-35`) — retry-снапшот только для очереди; отменённые генерации в журнале визуально неотличимы (`queue-log.js:72`); молчаливое вытеснение строк сверх 50 (`queue-log.js:19, 47-51`).
39. **Лайтбокс не закрывается тапом по фону** — `tapAction: 'toggle-controls'` по умолчанию (`lightbox.js:109-126`, вендор `photoswipe.esm.js:6550`); про свайп-вниз пользователь не знает.

## P3 — полировка (выборка)

- **«✕» означает «Свернуть»**, заголовка-аффорданса драга нет (`window.js:43-51`).
- **`font-weight: 600` на активной вкладке** дёргает ширину всего таб-бара (`style.css:253`).
- **Все аккордеоны по умолчанию открыты** (`accordion-state.js:26`) — простыни при первом визите.
- **Стена текста в «Данные и диагностика»**: 7 кнопок в ряд, скоуп деструктива «Очистить галерею» закопан в конце абзаца (`tab-settings.js:124-136`); секция «Поведение» — мешок из пяти несвязных настроек (`:75-93`).
- **Спейсинг-токены есть, но ритм дырявый**: литералы 3/5/7/9px рядом с `--uris-gap` (`style.css:1388, 870-874, 1140`); четыре рецепта теней без токенов (`:150, 198, 1071, 1819`); два диалекта «крестика на чипе» (`:926-940` vs `:1057-1063`); заголовок диалога масштабируется токеном иконки (`:1643`).
