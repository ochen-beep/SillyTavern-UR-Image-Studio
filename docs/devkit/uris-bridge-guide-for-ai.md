# Гайд для ИИ-агента: что должно поддерживать ваше расширение, чтобы генерировать изображения через URIS

> Вы — ИИ-агент, разрабатывающий стороннее расширение SillyTavern (телефон,
> визуальная новелла, генератор аватаров и т.п.). Заказчик хочет, чтобы ваше
> расширение запускало генерацию картинок силами **UR Image Studio (URIS)**.
> Этот документ — самодостаточный контракт: он составлен по коду моста
> (apiVersion 1) и описывает всё, что обязано поддерживать ваше расширение.
> Доступ к репозиторию URIS не требуется.

---

## 1. Как это работает (30 секунд)

URIS публикует в объект `globalThis.URIS` — «мост». Это обычный глобал
страницы: расширения SillyTavern живут в одном контексте, поэтому никаких
импортов из внутренностей URIS, серверных плагинов, ключей и CORS-настроек
не нужно. Всё, что делает URIS: ключи и соединения с провайдерами, доставка
запроса, recovery, галерея, Stop-кнопка, диагностика.

Ваше расширение отвечает только за **триггер и показ**: поймать момент
«нужна картинка» (клик, маркер в ответе LLM, ключевое слово), вызвать мост,
встроить результат в свой UI.

Важно понимать экономику: **каждый `generate()` — платный POST к провайдеру
изображений, каждый `buildPrompt()` — платный текстовый LLM-запрос** (деньги
пользователя). Мост пассивный: он никогда не решает сам, когда генерировать.

## 2. Обязательные требования к вашему расширению

Это минимальный список; без любого пункта интеграция считается сломанной.

1. **Быть обычным ST-расширением.** `manifest.json` + ES-модуль:

   ```json
   {
       "display_name": "My Extension",
       "loading_order": 110,
       "js": "index.js",
       "author": "you",
       "version": "0.1.0"
   }
   ```

   URIS имеет `loading_order` = 100; значение больше — грузитесь после него
   (глобал появится синхронно в вашем `init`). С клиентом из §4 порядок не
   важен. Обращения к ST API — ноль обязательных; мост не требует даже
   `SillyTavern.getContext()`.

2. **Константа `caller`** — стабильный id вашего расширения:
   `[A-Za-z0-9][A-Za-z0-9_-]{0,63}` (например `'my-phone'`). Он проставляется
   в каждый вызов, попадает в requestId (`ext_<caller>_<uuid>`), диагностику
   и карточку галереи — по нему пользователь видит, кто потратил запрос.
   Невалидный → ошибка `INVALID_CALLER` у пользователя. Задайте один раз
   константой, не генерируйте случайно.

3. **Обнаружение и ожидание моста — без кэша ссылки.**
   - Глобал `globalThis.URIS` публикуется в момент загрузки модуля URIS,
     но до окончания инициализации; готовность — через промис `URIS.ready`.
   - **Обращайтесь к `globalThis.URIS` в момент каждого вызова.** Если
     закэшировать объект, а пользователь выключит и включит URIS, ссылка
     умрёт: глобал пересоздаётся, старый объект абортит свои запросы.
   - Свой `init` не блокируйте на чужом `ready` дольше таймаута: URIS может
     быть не установлен. Нет моста → тихая деградация (кнопки генерации
     скрыты, расширение продолжает работать), никогда не падать при загрузке.
   - Повторный `ready` после отказа разрешён (rejection не вечен — URIS
     могут включить снова).

4. **Валидный запрос `generate`** (контракт в §5): `prompt` — непустая
   строка ≤ 100 000 символов; `aspectRatio`/`imageSize`/`quality` — только
   из допустимых списков (по умолчанию `'1:1'`/`'1K'`/`'auto'`); `references`
   — не более 8 элементов, каждый либо `{refId}` (id из пула URIS), либо
   `{dataUrl, name?}`, где `dataUrl` — `data:image/*;base64,…` или `http(s)://…`.
   Нарушения → `INVALID_PARAMS` (это ваш баг, а не сеть).

5. **Отмена через `AbortController`.** Каждый вызов — со своим `signal`;
   в UI на всё время ожидания — заготовка (pending) с работающей кнопкой
   отмены. Заброшенный вызов (промис без контроллера) отменить невозможно —
   пользователь платит за брошенное. Статусы прогресса приходят в `onStatus`.

6. **Обработка ошибок по `err.code`**, никогда по тексту сообщения
   (тексты меняются, коды — контракт). Полная таблица в §6.
   `ABORTED` — нормальный путь отмены: убрать заготовку молча, не показывать
   как ошибку.

7. **Результат — `imagePath`, показ через путь.** Возвращается постоянный
   файл SillyTavern вида `user/images/<папка>/uris_ext_<caller>_….png`:

   ```js
   img.src = '/' + result.imagePath;
   ```

   Храните у себя **путь**, не dataURL: путь переживает перезагрузку,
   мал и стабилен. Карточка в галерее URIS создаётся автоматически, вам
   ничего материализовывать не надо. Для vision-петли (показать картинку
   модели): `fetch('/' + imagePath)` → blob → dataURL.

8. **Платные вызовы — только по действию пользователя или явному согласию**
   (автогенерация — только если пользователь включил её в настройках ВАШЕГО
   расширения; лимиты частоты — на вашей стороне). Мост уже серийный: внешние
   вызовы идут по одному через общую очередь URIS — **не стройте своих
   параллельных очередей**.

9. **Реализовать свой триггерный слой.** Мост не подписывается на сообщения
   и не сканирует чаты — «когда генерировать» пишете вы: кнопка, ключевые
   слова, маркеры LLM, слеш-команда (рецепты в §8).

10. **Гигиена.** Не читать и не писать `extensionSettings.ur_image_studio`,
    не искать чужие ключи, не импортировать внутренние модули URIS — только
    глобал. Ключи соединений наружу не отдаются никогда
    (`listConnections()` отдаёт только `{id, label, modelId, ready}`).

## 3. Поверхность API v1 (`globalThis.URIS`)

| Метод | Вход → Результат |
|---|---|
| `ready` | промис (поле, не метод): резолвится после инициализации URIS |
| `apiVersion` | `1` — проверяйте перед использованием новых полей |
| `generate(req, opts)` | платная генерация картинки → `{requestId, cardId, imagePath, width, height, warnings}` |
| `buildPrompt(req, opts)` | платный Stage 1 (шаблон + резолвер сцены) над произвольным текстом → `{requestId, prompt, templateId, templateType, matchedReferences, ambiguities}` |
| `parseInline(text)` | синхронный, бесплатный: найти маркеры `[[тип: описание]]` → `[{type, desc, raw, start, end, profile}]` (в code-fence игнорируются) |
| `generateFromScene` | метода на мосте нет — это сахар клиента (buildPrompt → generate), см. §4 |
| `getStatus()` | `{enabled, ready, accepting, connection, active}` |
| `listConnections()` | `[{id, label, modelId, ready}]` — без endpoint'ов и ключей |
| `listRefs()` | `[{id, name, folders, bindingMode}]` — пул без payload'ов |
| `listTemplates()` | `[{id, name, type}]` — без тел промптов |
| `abort(requestId)` | `bool` — работает и для стоящего в очереди |
| `listActive()` | снапшот ваших/чужих внешних запросов: `[{requestId, caller, queued, startedAt}]` |
| `on(type, cb)` / `off(type, cb)` | события: `generation:queued/started/ended/error`, `prompt:started/ended/error`, `ready`, `destroyed`, `'*'`; возвращает unsubscribe |

События дублируются в `window` как `CustomEvent('uris:bridge')`
(`detail.type`, `detail.caller`, …). При выключении URIS диспатчится
`uris:bridge-destroyed`, глобал удаляется, все внешние запросы получают
`ABORTED`. События опциональны — весь мост request/response.

Мост включён, если расширение URIS включено и в его настройках не выключен
тумблер «Разрешить генерацию другим расширениям» (по умолчанию включён).
Иначе: `EXT_DISABLED` (URIS жив, мост закрыт) или `NOT_READY` (ещё
инициализируется).

## 4. Минимальный клиент (вставьте как есть)

```js
// uris-client.js — zero-dependency обёртка над globalThis.URIS
const CALLER = 'my-extension'; // ← константа вашего расширения

export async function urisReady(timeoutMs = 15000) {
    const t0 = Date.now();
    while (!globalThis.URIS) {
        if (Date.now() - t0 > timeoutMs) throw Object.assign(
            new Error('URIS not installed or disabled'), { code: 'URIS_UNAVAILABLE' });
        await new Promise(r => setTimeout(r, 150));
    }
    await globalThis.URIS.ready;          // ссылку НЕ кэшировать — см. §2.3
    return globalThis.URIS;
}

export async function urisGenerate(request, opts = {}) {
    const URIS = await urisReady();
    return URIS.generate(request, { caller: CALLER, ...opts });
}

// Сахар: текст сцены → промпт шаблоном URIS → картинка с автореференсами
export async function urisGenerateFromScene(
    { text, templateId, aspectRatio = '1:1', ...rest } = {}, opts = {}) {
    const URIS = await urisReady();
    const built = await URIS.buildPrompt(
        { text, templateId, useScene: true }, { caller: CALLER, ...opts });
    const result = await URIS.generate(
        { prompt: built.prompt, aspectRatio, useSceneRefs: true, ...rest },
        { caller: CALLER, ...opts });
    return { built, result };
}
```

В репозитории URIS есть более полный drop-in клиент: `docs/devkit/uris-client.js`
(методы `ready/isAvailable/generate/buildPrompt/generateFromScene/getStatus/
listConnections/listRefs/listTemplates/abort/onEvent`).

## 5. Контракт `generate(request, opts)`

```js
const result = await URIS.generate(request, {
    caller: 'my-extension',   // обязателен
    signal: ctl.signal,       // AbortSignal, настоятельно рекомендуется
    onStatus: (s) => updateUi(s),
    // queue: true (по умолчанию) — общая серийная очередь; false — сразу
});
```

`request`:

| Поле | Тип / допустимые значения | По умолчанию |
|---|---|---|
| `prompt` | непустая строка ≤ 100 000 символов | обязателен |
| `aspectRatio` | `1:1, 2:3, 3:2, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, 21:9` | `1:1` |
| `imageSize` | `1K, 2K, 4K` | `1K` |
| `quality` | `auto, high, medium, low` (не все провайдеры поддерживают — лишнее отбрасывается) | `auto` |
| `references` | массив ≤ 8: `{refId}` из пула URIS и/или `{dataUrl, name?}` (`data:image/*` base64 или `http(s)`) | `[]` |
| `connectionId` | id соединения URIS; иначе берётся соединение текущего чата | `null` |
| `modelId` | переопределить модель соединения (нет маршрута → `NO_ROUTE`) | `null` |
| `trigger` | id триггер-профиля URIS (`img`, `selfie`, `scene`, …; регистр и `ё` не важны): подставляет аспект и prompt-обёртку профиля; профиль с `refsPolicy: 'off'` запрещает автореференсы. Неизвестный → `TRIGGER_NOT_FOUND` | `null` |
| `useSceneRefs` | `true` — резолвер Stage 2 сам подберёт референсы, упомянутые в промпте (description-рефы впишутся в текст) | `false` |
| `expandMacros` | `false` — не разворачивать ST-макросы `{{char}}`/`{{user}}` и т.п. | `true` |

Референсы комбинируются; если ни `connectionId`, ни привязки чата нет —
`NO_CONNECTION`. Запрос не привязан к сообщению чата: `sourceMsgId = null`,
результат попадает в галерею URIS с пометкой вашего `caller`.

Результат: `{requestId, cardId, imagePath, width, height, warnings[]}`.
`requestId` — тег отслеживания, не стабильный id: для своего хранилища
используйте свои id, `cardId`/`imagePath` — ссылки на карточку и файл.

`buildPrompt({text, templateId?, useScene = true, expandMacros = true}, opts)`
— то же самое для текстовой стадии: запускает шаблон Stage 1 URIS над
произвольным текстом (не сообщения чата), возвращает готовый промпт и
список matched-референсов. Полезен, чтобы показать/закэшировать промпт до
платной картинки.

## 6. Коды ошибок (`err.code`) и что делать

| Код | Чья проблема | Действие |
|---|---|---|
| `URIS_UNAVAILABLE` (клиент) | среда | URIS не установлен/не появился — спрятать кнопки, подсказка |
| `NOT_READY` / `EXT_DISABLED` | конфигурация URIS | «инициализируется» / «мост выключен» — повторить позже или подсказка |
| `NO_CONNECTION` | конфигурация URIS | попросить выбрать соединение или передать `connectionId` |
| `NO_ROUTE` | ваш запрос | модель несовместима с соединением — сбросить `modelId` |
| `ROUTE_SELECTION_REQUIRED`, `MISSING_API_KEY`, `*_TOKEN_REQUIRED` | конфигурация URIS | показать `err.message` — он уже сформулирован для пользователя |
| `TRIGGER_NOT_FOUND` | ваш запрос | неизвестный `trigger` — в `err.message` список известных |
| `REF_NOT_FOUND` / `REF_UNAVAILABLE` | ваш запрос / файлы | `refId` нет в пуле или картинка не читается |
| `TEMPLATE_INVALID` / `NOT_FOUND` | конфигурация | шаблон пуст / не найден |
| `INVALID_PARAMS` / `INVALID_CALLER` | **ваш баг** | чинить на своей стороне, не ретраить |
| `ABORTED` | пользователь | **отмена — не ошибка**: убрать заготовку молча |

Ошибки — экземпляры `Error` с полем `code` (мостовые — класса
`UrisBridgeError`). Никогда не парсите текст сообщения.

## 7. Отмена, Stop, жизненный цикл

- Один `AbortController` на генерацию; `ctl.abort()` рвёт и стоящий в
  очереди (платный POST ещё не отправлен), и летящий запрос. Если POST уже
  ушёл, провайдер мог насчитать токены — URIS оставит pending-recovery
  запись для ручного разбора; потеря денег «молча» не бывает.
- **Stop таверны и Stop-кнопка URIS останавливают и мостовые запросы**
  (внутри это общий `activeGenerations`) — ловите reject `ABORTED` и убирайте
  заготовку, не оставляйте вечный спиннер.
- Выключение URIS посреди полёта: все внешние запросы получают `ABORTED`,
  глобал удаляется, диспатчится `uris:bridge-destroyed`. Повторное включение
  создаёт новый глобал — поэтому кэш ссылки запрещён (§2.3).
- `pagehide`/закрытие вкладки: запрос с `signal` обрывается браузером,
  состояние фиксируется в диагностике URIS.

## 8. Рецепты триггеров (что пишете вы)

- **Кнопка по требованию.** Клик → pending-заготовка → `generate` →
  `<img src="/"+imagePath>`. Простейший и рекомендуемый первый шаг.
- **Маркеры в ответах LLM** (персонаж «сам» шлёт фото). Обучите модель тегу
  в своём промпте (`<photo>описание</photo>`), парсите ответ **до показа**,
  на место тега ставьте заготовку, описание — в мост. Маркер оставляйте в
  сохранённом тексте (модель видит свои прошлые теги — формат
  самоподдерживается), юзеру не показывайте. Пустое/слабое описание —
  деградация (скрыть тег), не вызов моста. Для разбора инлайн-маркеров URIS
  вида `[[selfie: описание]]` есть бесплатный синхронный `URIS.parseInline(text)`.
- **Ключевые слова в сообщениях.** Слушайте события ST
  (`ctx.eventSource.on(ctx.event_types.MESSAGE_SENT, …)`), фильтруйте интент,
  генерируйте. Если картинка должна «прийти от персонажа» — генерируйте по
  `GENERATION_ENDED`.
- **Слеш-команда.** Зарегистрируйте свою через `ctx.SlashCommandParser` —
  она станет доступна из Quick Replies и STscript; возвращайте `imagePath`.
- **Перезагрузка страницы не должна стоить денег**: маркер/задачу в своём
  хранилище ключьте так, чтобы уже сгенерированный контент восстанавливал
  показ из сохранённого `imagePath`, а не запускал новую платную генерацию.

## 9. Чего НЕ делать

- Не кэшировать объект моста между вызовами.
- Не строить свою параллельную очередь — мост серийный, поверх неё
  получается двойная сериализация и голодание.
- Не звать `generate`/`buildPrompt` без `caller` и без `signal`.
- Не писать свой API-слой с ключами/endpoint'ами вместо моста.
- Не читать чужие настройки и папки, не импортировать модули URIS.
- Не проверять `globalThis.URIS` на верхнем уровне модуля одноразово —
  только в момент вызова или через `ready` с таймаутом.
- Не показывать `ABORTED` пользователю как ошибку.

## 10. Чек-лист приёмки

- [ ] `caller` — константа, валидная по `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`
- [ ] Готовность: `await URIS.ready` (с таймаутом) в момент вызова; ссылка на глобал не кэшируется
- [ ] Без URIS расширение работает: кнопки скрыты, `init` не падает и не висит
- [ ] Все `generate`/`buildPrompt` с валидными константами и ≤ 8 референсами
- [ ] Каждый вызов со своим `AbortController`+`signal`; pending-UI с отменой на всё время ожидания
- [ ] `err.code`-свитч на все коды из §6; тексты не парсятся; `ABORTED` — тихо
- [ ] `imagePath` сохраняется в вашем хранилище; показ `<img src="/"+path>`; перезагрузка не перегенерирует
- [ ] Платные вызовы — за действием пользователя или с его явного согласия
- [ ] Нет своего параллельного планировщика поверх моста
- [ ] `extensionSettings.ur_image_studio` не читается и не пишется
- [ ] Проверено: выключение URIS посреди генерации → заготовка убрана (не вечный спиннер); включение → работает снова

## 11. Как проверить

1. Консоль DevTools таверны: `typeof URIS` → `'object'`,
   `URIS.apiVersion === 1`, `await URIS.getStatus()`; одна тестовая
   генерация с `caller: 'selftest'` (платно — одной хватит).
2. Вкладка **«Мост»** в UI URIS (включается галкой «Показывать вкладку
   „Мост"» в настройках URIS): ручные вызовы `generate`/`buildPrompt`
   без консоли, со статусами и результатом.
3. Негативные: выключить тумблер моста → `EXT_DISABLED`; выключить URIS →
   глобал исчез + событие `uris:bridge-destroyed`; несуществующий `refId` →
   `REF_NOT_FOUND`; неизвестный `trigger` → `TRIGGER_NOT_FOUND`.
