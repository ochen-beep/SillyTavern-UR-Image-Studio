# URIS безопасный импорт/экспорт данных

**Дата:** 2026-07-16  
**Статус:** дизайн утверждён для подготовки реализации

## Цель

Сделать существующий импорт/экспорт UR Image Studio рабочим способом ручного backup и переноса данных между браузерами или установками SillyTavern без отдельного серверного плагина и без экспорта секретов.

Целевой сценарий — одна и та же SillyTavern или ручная миграция для продвинутого пользователя. Это не live-sync и не система разрешения конфликтов.

Галерея и изображения галереи в backup не входят. Переносятся библиотека референсов, настройки и остальные безопасные данные, которые уже обслуживает `data-port.js`.

## Принципы

1. **Секреты никогда не покидают локальное хранилище/ST secrets.** API-ключи пользователь вводит заново после импорта.
2. **Один источник данных в backup.** Не использовать дополнительную копию в `localStorage` и не делать локальный storage источником истины.
3. **Сначала полная валидация, потом запись.** Повреждённый или неподдерживаемый backup не должен оставлять частично импортированное состояние.
4. **Сохранять стабильные IDs.** Это позволяет восстановить ссылки bundles, templates, refs и chat-scoped записей.
5. **Явно сообщать ограничения.** В частности, не переносить галерею, учитывать исходный `chatId` и предупреждать о непереносимых путях изображений.
6. **Старый формат принимается.** Backup версии 2 адаптируется к новому внутреннему представлению без обязательного переписывания старых файлов.

## Объём backup

### Включается

- безопасные записи `localforage` с префиксом `uris_`;
- `extensionSettings[MODULE_NAME]` без секретных полей;
- библиотека референсов `uris_refs_pool`;
- папки `uris_refs_folders`;
- шаблоны, персонажи, параметры и bundles;
- описания image-коннектов без credentials;
- prompt history и instruction drafts, если они находятся среди разрешённых chat-scoped записей;
- URIS-поля привязки текущего чата, доступные через `chatMetadata`.

### Не включается

- `uris_gallery_*` и любые gallery entries;
- изображения галереи;
- `uris_custom_apikey`;
- `uris_conn_key_<connectionId>`;
- API-ключи, даже если случайно вложены в импортируемый объект;
- server secret IDs (`secretId`);
- всё, что не принадлежит URIS или не входит в разрешённую секцию backup.

Изображения референсов переносятся только в том виде, в каком они уже находятся в записи. Встроенный `dataUrl` переносим, но может сделать backup большим. Серверный `imagePath` переносится как ссылка и требует доступности соответствующего файла на целевой установке.

## Формат версии 3

Публичный JSON использует отдельные секции:

```js
{
  version: 3,
  module: "ur_image_studio",
  exportedAt: "2026-07-16T12:00:00.000Z",
  data: {
    localforage: {
      uris_refs_pool: [],
      uris_refs_folders: [],
      uris_prompt_templates: [],
      uris_bundles: []
    },
    extensionSettings: {},
    chatMetadata: {
      "chat-id": {
        refs: {},
        bundleId: "bundle-id",
        overrides: {}
      }
    }
  },
  secrets: {
    excluded: true,
    excludedKeys: ["uris_custom_apikey", "uris_conn_key_*"]
  }
}
```

Фактический набор `localforage`-ключей определяется allowlist-правилами. Нельзя принимать произвольные ключи только потому, что они начинаются с `uris_`: это снижает риск случайно экспортировать новый секрет или внутренний runtime-кэш.

В секции `chatMetadata` используется исходный `chatId`. Это осознанное решение для пользователей одной таверны/одного сервера и ручного backup. Импорт не пытается угадывать соответствие между разными чатами.

Поскольку публичный API SillyTavern предоставляет metadata текущего чата, экспорт обязан включать доступные URIS bindings текущего чата. Если другие chat-scoped записи уже находятся в `localforage`, они экспортируются по их ключам. UI и результат операции должны честно указывать, какие metadata были доступны для экспорта.

## Безопасность

### Экспорт

Перед сериализацией выполняется recursive sanitizer:

- удаляются поля `apiKey`, `api_key`, `token`, `password`, `secret`, `secretId` и их URIS-специфичные варианты;
- исключаются секретные localforage-ключи;
- `extensionSettings` очищается отдельно, затем проходит общий sanitizer;
- sanitizer не мутирует runtime-объекты.

Фильтрация ключей — первая линия защиты, recursive sanitizer — страховка от будущих изменений схемы или старых повреждённых записей.

### Импорт

Импорт:

- проверяет `module`;
- проверяет поддерживаемую версию и адаптирует v2;
- проверяет типы секций и допустимые ключи;
- игнорирует/удаляет secret-bearing поля;
- для imported connections принудительно выставляет `secretId: ''`;
- не удаляет существующие API-ключи при `replace`;
- не создаёт секреты без нового ключа, введённого пользователем.

Перед записью создаётся локальный rollback snapshot безопасных текущих данных. При ошибке записи выполняется попытка восстановить предыдущий snapshot и сообщается об ошибке без утверждения успешного импорта.

## Режимы импорта

### `merge`

- записывает импортируемые безопасные ключи;
- сохраняет локальные ключи, которых нет в backup;
- сохраняет стабильные IDs;
- не удаляет текущую галерею;
- не трогает текущие секреты;
- сбрасывает `secretId` у imported connections.

Для массивных коллекций merge использует существующее поведение импорта и не заявляет автоматическое разрешение конфликтов. Backup с более новой/старой записью определяется пользователем и порядком импорта.

### `replace`

- требует отдельного подтверждения;
- удаляет только разрешённые безопасные URIS-ключи, исключая галерею и секретные ключи;
- сохраняет API-ключи и текущую галерею;
- записывает содержимое backup;
- сбрасывает imported `secretId`;
- восстанавливает extension settings и доступные chat bindings;
- обновляет runtime-кэши и UI.

Перед `replace` пользователь видит состав backup и список того, что намеренно не будет заменено.

## UI

В настройках URIS возвращаются кнопки:

- **Экспорт данных**;
- **Импорт данных**.

Экспорт показывает количество разделов и скачивает файл `uris-backup-<timestamp>.json`.

Импорт сначала читает и валидирует файл, затем показывает сводку:

```text
Шаблоны: N
Референсы: N
Папки: N
Бандлы: N
Коннекты без ключей: N
Chat bindings: N
Галерея: не включена
API-ключи: не включены
```

Пользователь выбирает `merge` или `replace`. Для `replace` требуется явное подтверждение. После успешного импорта UI получает уведомление о необходимости повторно ввести ключи для коннектов без credentials.

После импорта приложение обновляет список коннектов, шаблонов, refs и cache пула референсов; активный bundle и текущая вкладка перечитываются без перезагрузки, насколько это поддерживается текущим UI.

## Миграция и совместимость

- `BACKUP_VERSION` повышается до 3.
- Существующий v2 `{ keys, extensionSettings }` преобразуется адаптером в секции v3.
- Старые v2 secret-bearing keys дополнительно фильтруются во время адаптации.
- Нет автоматической миграции gallery: старые gallery keys не должны попадать в новый экспорт и не должны восстанавливаться из backup.
- Stable IDs не перегенерируются.
- Поля, неизвестные текущей схеме, не должны становиться причиной записи произвольных localforage-ключей.

## Тестирование

Добавляются тесты:

1. export/import round-trip для refs, folders, templates, bundles, connections без ключей и разрешённых chat-scoped записей;
2. экспорт никогда не содержит API-ключи, `secretId` или вложенные secret-поля;
3. gallery не попадает в экспорт и не удаляется при `replace`;
4. `merge` сохраняет локальные безопасные данные, отсутствующие в backup;
5. `replace` удаляет только разрешённые безопасные записи и оставляет secrets;
6. импорт v2 адаптируется и не восстанавливает секреты;
7. некорректный backup отклоняется до первой записи;
8. ошибка записи запускает rollback;
9. после импорта обновляются refs pool cache и connection state;
10. chat bindings сохраняются с исходным `chatId` и не получают автоматического remapping.

## Не входит в эту задачу

- автоматическая синхронизация между браузерами;
- live sync и conflict resolution;
- отдельный серверный плагин SillyTavern;
- перенос gallery и image assets;
- экспорт API-ключей;
- автоматическое сопоставление chat IDs между разными установками;
- cloud backup или внешний backend.
