# Паритет с Figma-макетом: папки референсов, поля API-карточек, лимит референсов

Дата: 2026-07-29

## Контекст

Сверка макета Figma (5 скриншотов: таб API и таб «Референсы») с текущей
реализацией показала, что крупные блоки уже на месте: тумблер Профиль/Свой с
подписью модели, баннер «Авто-режим» с «Перепроверить», аккордеон-карточки
server-коннектов с сохранением свёрнутости, сетка карточек 3:4 с role-бейджем и
точками папок, оверлей-редактор, загрузка и сжатие изображений, алиасы и
автораспознавание, фильтрация по папкам.

Расхождения делятся на четыре независимых блока. Три из них — недостающая
функциональность и косметика, один — баг, который блокирует рабочую фичу.

Из объёма сознательно исключены поля «Референсы» (режим доставки) и «Максимум»
на server-карточках: маршрут сообщает свои возможности сам, а надёжно узнать
предел конкретной модели нельзя (см. блок D).

## Блок D: лимит референсов на server-коннектах (баг, делается первым)

### Проблема

`generateImageRequest` (`src/image-api.js:88-90`) для server-коннекта уходит в
`generateServerOwnedImage` до вычисления политики, поэтому `resolveReferencePolicy`
и `prepareReferences` (строки 124-126) на этом пути не работают. Реальный лимит
применяет сервер в `validateReferences` (`server-plugin/src/services/generation.js:34-41`):
потолок `MAX_REFERENCES = 16`, плюс `route.capabilities.maxReferences`, если это
целое число; превышение — ошибка `TOO_MANY_REFERENCES`, а не тихое отсечение.

Панель референсов в «Генерации» берёт лимит из `getActiveReferencePolicy`
(`src/ui/tab-generate.js:853-871`), а та вызывает `getImageProvider(apiType)`. В
реестре остались только `pollinations`, `agnes`, `comfyui`, `a1111`
(`src/providers/registry.js:22-27`), тогда как у server-коннекта `apiType` — это
`openai-images` / `gemini-native` / `openrouter-images` (`src/connections.js:145`).
Провайдер не находится, и функция возвращает
`{ supported: false, maxRefs: 0, reason: 'Неизвестный тип API: gemini-native' }`.
UI сообщает, что референсы не поддерживаются, и запрещает добавление, хотя сервер
их примет.

### Решение

В `getActiveReferencePolicy` добавляется ветка для server-коннектов до обращения
к реестру браузерных провайдеров:

```js
if (isServerOwnedConnection(conn)) {
    const caps = conn.selectedRoute?.capabilities;
    if (caps?.references === 'unsupported' || caps?.maxReferences === 0) {
        return { supported: false, maxRefs: 0, reason: 'Выбранный маршрут не принимает референсы.' };
    }
    const routeMax = Number.isSafeInteger(caps?.maxReferences) && caps.maxReferences > 0
        ? caps.maxReferences : MAX_REFS;
    return { supported: true, maxRefs: Math.min(MAX_REFS, routeMax), protocol: null, reason: '', source: 'server-route' };
}
```

Неизвестность (`references: 'unknown'`, `maxReferences: null`) трактуется как
«разрешено до `MAX_REFS`» — так же, как её трактует сервер. Явный ноль отсекается
отдельной проверкой, иначе `maxReferences: 0` при `references: 'supported'` дал бы
4. `MAX_REFS` уже импортирован (`tab-generate.js:18`); добавляется только импорт
`isServerOwnedConnection`.

`buildReferencePanelState` (`tab-generate.js:153-174`) не меняется: она уже
корректно работает с любым `{ supported, maxRefs, reason }`.

Почему цифру не угадываем. Достоверный `maxReferences` приходит только от
OpenRouter (`max_input_references`, `openrouter-images.js:108-112,125`) и от
OpenAI-совместимых каталогов, отдающих `capabilities.max_input_images`
(`openai-images.js:52-56`). `gemini-native.js:117` и ручной маршрут
(`coordinator.js:84`, `server-connection-form.js:58`) честно ставят `null`.
Лимиты бывают жёсткие (API вернёт 400) и мягкие (примет, но качество упадёт), и
зависят ещё от протокола доставки и от поведения прокси-шлюза. Одно число это не
описывает, поэтому авторитетом остаётся ответ сервера.

## Блок A: управление папками референсов

### Проблема

`renameFolder` и `deleteFolder` импортируются в `src/ui/tab-references.js:10` и не
вызываются ни разу — мёртвые импорты. `FOLDER_COLOR_PALETTE`
(`src/refs-library.js:128-131`, ровно 10 цветов из макета) не импортируется ни
одним UI-файлом: цвет назначается циклически по индексу при создании и не
меняется. API для смены цвета отсутствует.

### Решение

В `src/refs-library.js` добавляется `updateFolder(id, patch)`, принимающая `name`
и `color`; валидация цвета уже есть в `normalizeFolder:138`. `renameFolder`
остаётся как тонкая обёртка — на неё опираются существующие тесты.
`deleteFolder` уже корректно осиротняет карточки (`:176-194`) и только
подключается к UI.

В десктопном сайдбаре (`_renderSidebar`, `tab-references.js:78-113`) у каждой
пользовательской папки появляется иконка карандаша. Клик раскрывает инлайн-форму
под строкой папки:

- инпут имени;
- сетка из 10 свотчей `FOLDER_COLOR_PALETTE`, выбранный помечен;
- кнопки ✓ (применить) и ✗ (отменить);
- «Удалить папку» с подтверждением через `showConfirmModal`.

Состояние — новая модульная переменная `_editingFolderId`, открыта не более одной
формы за раз. Карандаш не появляется у псевдо-папок «Все карточки» и «Без папки».

Палитра верстается flex-wrap, поэтому в узком сайдбаре (170px) укладывается в три
ряда, как на скриншоте 3, а в широком одностолбцовом виде — в один ряд, как на
скриншоте 2. Отдельных медиа-запросов не требуется.

Превью-миниатюры в десктопный сайдбар не добавляются: в макете там только точка,
имя, счётчик и карандаш. Текущее поведение совпадает.

## Блок B: паритет полей API-карточек

Поле «Тип API» переезжает из блока `canManual`
(`src/ui/server-connection-form.js:127-135`) наружу и показывается всегда. Это
семантически корректно: `apiFamilyOverride` передаётся в зонд (`:237`), то есть
поле осмысленно до пробы, а не только при провале каталога. «Model ID» остаётся
внутри `canManual` — ручной ввод модели нужен лишь когда каталог не ответил.

Локализация формы: Endpoint → «URL endpoint», API key → «Ключ», Route →
«Модель», Probe/Refresh → «Проверить»/«Обновить», Save → «Сохранить», Delete →
«Удалить», плейсхолдер имени → «Имя коннекта». Кнопка добавления
(`src/ui/tab-api.js:321`) → «+ Добавить коннект».

Поля «Референсы» и «Максимум» не добавляются.

## Блок C: полировка карточек референсов

Кнопка «Сохранить» в оверлей-редакторе. Сейчас автосохранение висит на событии
`change` (`tab-references.js:431-434`), а у textarea оно срабатывает по blur:
набранное описание теряется, если закрыть оверлей крестиком. Явный коммит по
кнопке решает это; автосохранение по `change` остаётся как страховка.

Остальное косметика:

- role-бейдж получает цвет из уже объявленных `--uris-role-char/user/npc`
  (`style.css:51-53`) вместо нейтрального серого (`style.css:1042-1047`);
- «Заменить» позиционируется поверх превью в правом нижнем углу;
- в мобильный тулбар (`tab-references.js:276`, `:334`) добавляется поиск;
- «Все» → «Все карточки» (`:95`);
- опечатка «Без папка» → «Без папки» (`:98`).

## Порядок и проверка

Порядок: D → A → B → C. Сначала баг, затем функциональность, косметика
последней. Блоки независимы и могут проверяться по отдельности.

Тесты — встроенный раннер Node: `node --test tests/*.test.js`. Перед началом
работы прогоняется базовый прогон, чтобы отделить новые поломки от 14
незакоммиченных файлов в `server-plugin/`.

Новые кейсы:

- `updateFolder` в `tests/refs-library.test.js`: валидный цвет, битый цвет
  (падает на дефолт палитры), несуществующий id (возвращает `null`);
- инлайн-форма папки в `tests/tab-references.test.js`: раскрытие по карандашу,
  применение имени и цвета, отмена, удаление;
- ветка server-роута в `tests/tab-generate.test.js`: `unknown` → 4, число из
  capabilities → `min` с `MAX_REFS`, явный ноль → `supported: false`;
- постоянная видимость «Тип API» в `tests/tab-api-server-connections.test.js`.
